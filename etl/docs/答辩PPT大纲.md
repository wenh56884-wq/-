# 答辩 PPT 大纲（10 页）

> 本大纲所有字段名与数值取自 `engine\` / `agents\tools.py` 的真实返回，
> 演示样例：班级 `AI2201`、学生 `AI2022001 陈鹏`、学期 `2025-2026-2`。
> 每页讲稿按 30 秒语速写（约 120 字），10 页合计约 5 分钟。

---

## 第 1 页 · 封面

**标题**：启航 —— 基于大数据与多智能体协同的生涯与岗位匹配系统

**要点**
- 一句话定位：**学业预警算得准、岗位推荐讲得清**
- 两条业务链路：教师端（预警 / 画像 / 职业差距）+ 学生端（本人预警 / 岗位推荐）
- 技术底座：MySQL + DuckDB + FastAPI + LangGraph + Vue 3
- 演示规模：学生 500 人 / 岗位 2931 条 / 画像特征 500 行（`calc_version=v1.1`）

**画面**：系统登录页截图；右下角标注版本号 `warning-v2 · profile-v1.1 · recommend-v1.0`

**讲稿**
> 各位老师好，我做的系统是"启航"。它解决的是高校里两个真实痛点：辅导员靠人工排查看不出谁在被学业拖垮，学生到大四才发现自己的能力和岗位要求差在哪。系统现在跑的是真实规模数据：500 名学生、2931 条真实招聘岗位。

---

## 第 2 页 · 痛点（教师端 / 学生端各 2 条）

**标题**：为什么现在这套流程不够用

**要点**
1. 教师端：**名单滞后** —— 挂科、出勤、下滑分散在多张表，人工拼表赶不上学期节奏
2. 教师端：**缺少归因** —— 只看到"某人不及格"，看不到 `risk_score=100` 背后的 `reasons`
3. 学生端：**自我认知模糊** —— 不知道自己与目标岗位的差距是 SQL 还是项目经历
4. 学生端：**推荐不可解释** —— 只给"适合你"，不给 `hit_items / gap_items`

**画面**：左半页"人工拼表"示意；右半页截 `GET /teacher/warnings` 的真实 JSON（`level=red`、`coverage=3`）

**讲稿**
> 教师这边有两个痛点：一是数据分散，二是只有结论没有归因。学生这边也有两个：不知道差在哪，推荐也不可解释。我们系统输出的每个数字，都会同时给出它是怎么算出来的。

---

## 第 3 页 · 系统架构图（四层）

**标题**：四层架构 —— 数据层 / 引擎层 / 智能体层 / 应用层

**要点**（自下而上）
- 数据层：MySQL（`student / score / job / job_view_log / elective_selection`）+ DuckDB（`student_feature / job_feature / recommend_log`）
- 引擎层 `engine\`：确定性计算唯一真相源 —— `warning.py` / `profile.py` / `recommend.py` / `career_rules.py`
- 智能体层 `agents\`：LangGraph `graph.py` 编排，`critic.py` 数值回查，`tools.py` 防越权取数
- 应用层：FastAPI（`app\`）+ Vue 3（`web\`），前端禁止直连数据库

**画面**：四层架构图；用两种颜色区分"负责算数的"与"负责说话的"

**讲稿**
> 架构上我把"算数"和"说话"彻底分开：下面两层负责计算，上面两层只做表达。中间这道闸门是 Critic —— 大模型写出的一句话里每个数字都要回查，查不过就降级，不允许出现模型自己编的数。

## 第 4 页 · 模块一 预警引擎（三档 + 租户阈值 + 真实归因）

**标题**：学业预警 —— 三档色 + 缺失不冒充

**要点**
- 三条指标：`fail_count`（挂科门次）+ `gpa_drop`（均分下滑）+ `attendance_rate`（出勤率）
- 三档色：`level = red / orange / yellow`，另有 `none` 与灰档 `unknown`
- **缺失不冒充**：`normalize_metrics` 缺数据写 `None`，输出 `coverage / missing`，`factor = 总权重/可用权重`
- 阈值可调：租户表 `warning_threshold` 覆盖 `rules.WarningRules`，**改数值不改算式**
- 真实归因（AI2201 班 AI2022001 陈鹏）：`risk_score=100 / level=red`
  `reasons = ["本学期挂科6门", "本学期平均成绩下滑35.17分", "本学期出勤率降至57.9%"]`

**画面**：三色统计卡 + 分布柱状图 + 名单展开行；右侧贴 `metrics` 原始值

**讲稿**
> 预警不是简单拍脑袋给等级。三条指标各自打分加权，缺一项就如实写进 `missing`，并把权重在剩余项里重归——少数据会让人更危险，而不是更安全。这位同学 100 分红档，系统给的归因是挂科 6 门、下滑 35.17 分、出勤 57.9%，辅导员可以直接照着这三句去谈话。

## 第 5 页 · 模块二 四维画像（雷达图 + 标签）

**标题**：学生画像 —— 学业 / 行为 / 兴趣 / 能力

**要点**
- 四维：`dimensions = {"study": …, "behavior": …, "interest": …, "ability": …}`，取值 0-1
- 标签：`tags = ["专业后50%", "偏好数据岗", "能力履历完整", "学业急剧下滑"]`
- 样例（陈鹏）：`study=0.2001 / behavior=0.3995 / interest=0.5233 / ability=0.8`
- 成绩趋势：`gpa_trend_series = [{2025-2026-1: 81.17}, {2025-2026-2: 46.0}]`
- 口径统一：`class_rank_pct`（班级口径）与 `major_rank_pct`（专业口径）**分列存储**，学业标签只认专业口径；`library_activity` 按 0-1 直存（`DECIMAL(5,4)`）

**画面**：抽屉里的 ECharts 雷达图 + 标签；下方一条两学期的 GPA 趋势折线

**讲稿**
> 画像看四个维度。雷达图里一眼就能看出：这位同学能力维 0.8 还不错，学业维只有 0.2。标签系统同时给出"偏好数据岗"和"学业急剧下滑"两个方向相反的信号——这正是辅导员最需要的信息：他不是没兴趣，是跟不上了。

## 第 6 页 · 模块三 可解释推荐（三段式理由）

**标题**：岗位推荐 —— 四维打分，每一条都带理由

**要点**
- 打分：`major_match 0.35 + gpa_gate 0.25 + skill_cover 0.30 + interest_fit 0.10`，`final_score` 保留 4 位
- 冷启动：无技能无兴趣数据时 `cold_start=true`，只用 `major_match + gpa_gate`
- 硬约束：**不调大模型、不用随机数**；同输入同结果（排序键 `-final_score, -salary_max, job_id`）
- 真实样例（Top1）：`大数据分析师（上海，8000-12000）final_score=0.7742`
- 三段式理由：
  - `hit_items = ["专业完全匹配", "技能覆盖 6/9", "后端 与 数据 属相关方向"]`
  - `gap_items = ["岗位要求sql，你的课程记录未体现", "…", "成绩低于门槛 20.0 分"]`
  - `advice = "建议选修《数据库原理》并完成一个实战项目"`

**画面**：学生端推荐列表截图，绿=命中 / 橙=缺口 / 底部建议段

**讲稿**
> 推荐的三段式理由是"命中项、缺口项、建议"。命中项告诉学生哪儿行，缺口项告诉他差哪门课，建议直接指到课程名。这套输出全部由规则生成，没经过大模型掺手，所以同一份输入跑一万次结果完全一样。

## 第 7 页 · 模块四 多智能体（LangGraph + 防越权双防线）

**标题**：LangGraph 编排与两道防线

**要点**
- 编排：`agents\graph.py` 里 `plan → tool → draft → critic → accept/fallback`
- 铁律：**Agent 不碰数值**，`tools.py` 返回结构化结果，模型只负责组织语言
- 防线一（身份）：`student_id / teacher_id` 只由 JWT 注入（`app\auth.py`），学号不接收外部传参
- 防线二（租户）：数据层 `tenant_id` 过滤 + `PermissionError → HTTP 403`，前端隐藏只是体验优化
- Critic：`critic.py` 逐条回查数字，最多重试 2 次，超限降级为模板输出（`degraded=true`）

**画面**：LangGraph 图（含重试回路）+ 403 弹回登录页截图 + `audit_log` 表片段

**讲稿**
> 智能体这一层我设了两条红线：一是数值只能来自引擎，Critic 会逐句回查数字，查不过就降级，不让学生看到未核对过的数；二是身份只能来自登录态，学生直接调教师接口会被 403 弹回登录页，而且每次请求都写 `audit_log` 留痕。

## 第 8 页 · 创新点（确定性计算 / 表达生成性）

**标题**：三条硬约束，构成可信边界

**要点**
1. **确定性计算、表达生成性**：分数、排名、门次、比例、人数全由 `engine\` 产出，LLM 不得生成或修改数值
2. **Critic 数值回查**：输出里的每个数字必须与引擎结果一致，不一致驳回重生成，超限降级
3. **多租户隔离在数据层**：越权请求到不了应用层，伪造请求也拿不到别校数据
4. **缺失不冒充**：`unknown` 灰档 + `coverage/missing`，"没数据"绝不等于"正常"

**画面**：对照图（旧实现：缺考勤当全勤 → 54 分橙档；新实现：缺失项权重重归 → 81 分红档）

**讲稿**
> 我最想强调的是"缺失不冒充"这一条。旧实现把没有考勤记录的学生当全勤处理，算出 54 分橙档；改完之后同一个人是 81 分红档。没有数据就是没有数据，系统宁可给灰档，也不给虚假的安全感。

## 第 9 页 · 演示与验证（12 项冒烟 + 幻觉抽检）

**标题**：怎么证明它真的能跑

**要点**
- 一键冒烟：`powershell -File scripts\smoke_test.ps1` → **PASS 12 / FAIL 0 / SKIP 0**（约 2.5 秒）
- 覆盖：健康检测 / 教师登录 / 班级概览 / 预警名单 / 画像 / 职业差距 / 学生登录 / 本人预警 / 越权 403 / 推荐 v1.0 / 静态托管 / 静态资源
- 数值一致性（20 人级抽查）：`gpa_drop == -gpa_trend` 20/20、教师端与学生端一致 20/20、推荐三件套齐全 20/20
- 幻觉抽检：把 Draft 写成"平均绩点 88.8、挂科率 0.9"，Critic 全部驳回，重试用尽后降级为无数值话术
- 一键验收：`python scripts\gen_verify_report.py` 生成 `docs\VERIFY.md`

**画面**：冒烟终端输出截图 + VERIFY.md 表格 + 幻觉被拦截的日志片段

**讲稿**
> 验收我做成了脚本化的：一个冒烟脚本 12 项全绿，一个报告生成器自动出环境水印和数据一致性表。还有专门的幻觉测试——故意让模型编一个数，Critic 会拦下来；反复拦不住就降级成不含任何数字的安全话术。

## 第 10 页 · 下一步（二期）

**标题**：从单机到分布式，从规则到混合推荐

**要点**
- 环境升级：JDK 17 + PySpark 4.0，`engine\profile.py` 的纯函数原样迁到 Spark DataFrame
- 口径不漂：迁移后用同样 500 名学生逐字段比对，**一致率必须 100%**
- 混合推荐：规则打分基础上加协同过滤（同专业、成绩 ±5 分），`final = 0.7*A + 0.3*B`，冷启动整段跳过
- 治理护栏：校验要覆盖"引用了库里没有的行/列"，宁可判定不通过也不许编

**画面**：二期路线图时间轴；标出当前位置"单机版全链路已打通"

**讲稿**
> 二期主要做三件事：把画像层迁到 Spark 跑量、给推荐加协同过滤、把治理校验再补严。现在架构就是按这个方向设计的——引擎层全是纯函数，迁 Spark 时口径可以逐字段核对，一旦漂移立刻能发现。

## 附：名词对照（答辩口径统一）

| 字段名 | 含义 | 出处 |
|---|---|---|
| `risk_score` | 0-100 风险分（加权和 · 缺失时权重重归） | `engine\warning.py` |
| `coverage / missing` | 可用指标数 / 缺失指标清单 | `engine\warning.py` |
| `unknown` | 灰档：数据不足，不等于正常 | `engine\rules.py` |
| `class_rank_pct / major_rank_pct` | 班级 / 专业口径排名百分位（0=第一） | `engine\profile.py` |
| `dimensions` | 四维画像得分（study/behavior/interest/ability） | `engine\profile.py` |
| `final_score` | 岗位推荐总分（`double` 保留 4 位） | `engine\recommend.py` |
| `hit_items / gap_items / advice` | 三段式理由 | `engine\recommend.py` |
| `degraded` | Critic 未通过后的降级标记 | `agents\graph.py` |
