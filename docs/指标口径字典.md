# 指标口径字典（唯一事实来源 / Single Source of Truth）

> 版本 v1.1 · 2026-10-26 · 适用范围：`engine\warning.py`、`engine\profile.py`、`engine\recommend.py`、`agents\tools.py`、`web\`
> **铁律：任何引擎新增/修改指标，必须先改本文件，再改代码。代码与本文件冲突时，以本文件为准并回改代码。**

## 0. 为什么要这份文件

同一批学生在预警引擎和画像引擎里被反复计算，只要有一个指标的方向、分组、缺失策略不一致，就会出现「教师端说下滑、画像说进步」「班级前 20% 却贴专业后 50% 标签」这类自相矛盾。这类 bug 不会报错，只会在答辩现场被评委问倒。

## 1. 指标总表

| 指标 | 定义（公式） | 方向 | 取值域 | 分组/口径 | 缺失策略 |
|---|---|---|---|---|---|
| `gpa` | 本学期所选课程成绩算术平均 | 越大越好 | 0–100 | 学期 × 学生 | 无成绩 → `None` |
| `fail_count` | 本学期 `<60` 分的课程门数 | 越大越差 | 0–n | 学期 × 学生 | 无成绩 → `None` |
| `gpa_delta` | **本学期 gpa − 上学期 gpa** | **正数 = 进步** | −100–100 | 学期 × 学生 | 无上学期 → `None` |
| `gpa_trend` | 同 `gpa_delta`（画像侧字段名） | 正数 = 进步 | −100–100 | 同上 | 同上 |
| `gpa_drop` | `−gpa_delta`（预警侧字段名，正数 = 下降） | **正数 = 下降** | −100–100 | 同上 | 同上 |
| `class_rank_pct` | 班内 gpa 降序，`i/(n-1)` | **0 = 班级第一，1 = 末位** | 0–1 | **按 `class_name` 分组** | 单人班 → 0.0 |
| `major_rank_pct` | 专业内 gpa 降序，`i/(n-1)` | **0 = 专业第一，1 = 末位** | 0–1 | **按 `major` 分组** | 单人专业 → 0.0 |
| `attendance_rate` | `(总课时 − 缺勤) / 总课时` | 越大越好 | 0–1 | 学期 × 学生 | 无考勤 → `None`（**不得按 1.0 处理**） |
| `library_visit_cnt` | 学期到馆/借阅原始次数 | 越大越好 | 0–n | 学期 × 学生 | 无记录 → `None` |
| `library_activity` | `min(1, library_visit_cnt / 60)` | 越大越好 | **0–1** | 学期 × 学生 | 无记录 → `None` |
| `consumption_regularity` | 一卡通消费规律性（由消费频次标准差换算） | 越大越好 | 0–1 | 学期 × 学生 | 无记录 → `None` |
| `course_pref` | `{方向: 选修门次}` | — | map | 学期 × 学生 | 空 → `{}` |
| `job_view_pref` | `{方向: 浏览次数}`，合成时权重 ×0.5 | — | map | 学期 × 学生 | 空 → `{}` |
| `cert_count` / `contest_count` / `project_cnt` | 证书 / 竞赛 / 项目个数 | 越大越好 | 0–n | 学期 × 学生 | 无记录 → `None`（**不得按 0 处理**） |

### 1.1 三个最容易搞错的点

1. **`gpa_delta` 与 `gpa_drop` 符号相反**。预警侧沿用「下降多少分」的正数习惯（`gpa_drop = 上期 − 本期`），画像侧沿用「趋势」习惯（`gpa_trend = 本期 − 上期`）。两者**必须是同一个量的相反数**，任何一处正负号写反都会静默出错 → 由 `tests\test_metric_consistency.py` 强制断言 `gpa_drop == -gpa_trend`。
2. **`class_rank_pct` 与 `major_rank_pct` 方向相同（都是越小越靠前），差的是分组**。所以它们**不是同一个指标**，不能共用一列。画像标签「专业前 20%」只能读 `major_rank_pct`；教师端看板「班级排名」只能读 `class_rank_pct`。
3. **`library_activity` 是 0–1 的归一化值，不是次数**。次数放在 `library_visit_cnt`（INTEGER）。旧版把它塞进 INTEGER 列再 ×100 存储，属于口径污染，v1.1 已拆分。

## 2. 归一化规则（画像用）

统一「固定上下界 min-max + clamp」，**不依赖批次分布**，保证 PySpark 逐行复现（map-only，无 shuffle）。

| 子指标 | 上界常量 | 下界常量 | 说明 |
|---|---|---|---|
| `gpa` | `GPA_MIN=0` | `GPA_MAX=100` | |
| `gpa_trend` | `TREND_MIN=**-40**` | `TREND_MAX=20` | v1.1 由 −20 放宽：实测存在 −35.17 的极端退步，−20 会把极端值吞成 0（与「无变化」无法区分） |
| `fail_count` | `FAIL_CAP=3` | — | `1 - min(1, n/3)`，0 门 = 1.0 |
| `library_activity` | `LIBRARY_CAP=60` | — | `min(1, cnt/60)` |
| `course_pref`（门次合计） | `PREF_CAP=6` | — | |
| `job_view_cnt` | `JOB_VIEW_CAP=50` | — | |
| `job_favorite_cnt` | `JOB_FAV_CAP=20` | — | |
| `cert_count` | `CERT_CAP=3` | — | |
| `contest_count` | `CONTEST_CAP=2` | — | |
| `project_cnt` | `PROJECT_CAP=2` | — | |

**极端值不静默裁剪**：`gpa_trend <= -30` 时除归一化外，额外打标签 `学业急剧下滑`（`extreme_decline`），保证极端退步在界面上可见，而不是被 clamp 掉。

## 3. 缺失数据策略（「缺失不冒充」）

### 3.1 画像引擎（已达标，保持）
- 缺失子指标为 `None`，**不参与**加权，剩余权重按比例归一（`_weighted_mean`）；
- 整行无任何数据 → `has_data=False`，标签 `["数据不足"]`；
- 维度全部缺失 → 维度得分 `None`，标签 `学业数据不足` / `能力数据不足`。

### 3.2 预警引擎（v1.1 必须改，当前在冒充）
现状问题（`engine\warning.py: normalize_metrics`）：

| 字段 | 现状 | 问题 | v1.1 要求 |
|---|---|---|---|
| `attendance_rate` | 缺失 → `1.0` | **把「没数据」当成「全勤」**，直接少算一条风险，风险被系统性低估 | 缺失 → `None`，该指标不参与加权 |
| `gpa` | 缺失 → `0.0` | 会伪装成「成绩极差」 | 缺失 → `None` |
| `fail_count` | 缺失 → `0` | 伪装成「没挂科」 | 缺失 → `None` |
| `rank_pct` | 缺失 → `0.0`（= 第一名） | 伪装成「班级第一」，且该字段当前未参与打分（死字段） | 删除或改名为 `class_rank_pct` 仅供展示 |

**新规则**：
1. `evaluate_student` 输出新增 `coverage`（0–3，实际可用的打分指标数）与 `missing`（缺失指标名列表）；
2. `risk_score` 只对**可用指标**加权，权重在可用项内重新归一（与画像引擎同一套逻辑，**禁止**再用默认值填充）；
   实现细节：`factor = Σ三项 weight / Σ可用项 weight`，**仅当 coverage ≥ 2 时启用**；
   `coverage < 2` 时 `factor = 1.0`（只有 1 项可用时外推会把 1 门挂科放大成 45 分，凭空造出高风险档，比不放大更糟）；
3. `coverage < 2` → `level = "unknown"`（灰档），`reasons = ["数据不足，无法评估"]`，**不得标为绿色（正常）**；
4. 前端灰档文案：`数据不足 · 请联系教务补录`。

## 4. 落库字段（DuckDB `student_feature`, v1.1）

| 列 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `class_rank_pct` | `DECIMAL(5,4)` | profile 侧同时计算并写入（按 `class_name` 分组） | 新增；0=班级第一。教师端看板由 warning 侧实时重算同名指标，两者公式一致 |
| `major_rank_pct` | `DECIMAL(5,4)` | profile 侧计算 | **由旧 `rank_pct` 改名而来**；0=专业第一 |
| `library_visit_cnt` | `INTEGER` | 原始次数 | 新增 |
| `library_activity` | `DECIMAL(5,4)` | 0–1 归一值 | **类型由 INTEGER 改为 DECIMAL(5,4)**，取消 ×100 折中 |
| `gpa_trend` | `DECIMAL(5,2)` | 本期 − 上期 | 正数 = 进步 |
| `extreme_decline` | `BOOLEAN` | `gpa_trend <= -30` | 新增，界面据此加红色警示 |

`student_feature` 是**派生表**（可由 MySQL 重算），因此允许 `DROP TABLE` 后按新 schema 重建，不需要兼容旧列。

## 5. 一致性测试（必须存在，缺一即打回）

`tests\test_metric_consistency.py` 至少 5 个用例：

1. 同一份原始数据，`warning.fetch_*` 得到的 `gpa_drop` 与 `profile.fetch_student_raw` 的 `gpa_trend` 满足 `gpa_drop == -gpa_trend`；
2. `class_rank_pct` 与 `major_rank_pct` 在同一班组内可以不同，且各自都满足 0≤x≤1、组内第一名 = 0；
3. 缺失出勤数据时，预警结果 `coverage == 2`、`risk_score` 不因「默认为全勤」而变低；
4. 仅 1 项可用指标时 `level == "unknown"`；
5. `library_activity` 落库后读回仍为 0–1 区间（误差 < 0.0001）。
