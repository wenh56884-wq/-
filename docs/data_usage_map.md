# 启航数据用途映射（表 → 用途 → 板块 → 看点）

> **口径说明**：盘点日期 2026-11-16。行数来源为 MySQL `information_schema` 实查（库 `qihang`，共 53 张表）；
> 引用来源为代码扫描（`engine/`、`agents/`、`app/`、`web/` 的产品路径；`scripts/` 仅造数，不算产品用途）。
> 本轮新增「校园行为洞察」板块（学生端 `/student/campus`、教师端 `/teacher/campus`），
> 把此前只有脚本/后台引用的 6 张表（图书馆记录、消费记录、学生活动、岗位浏览日志、周快照、学生扩展信息）
> 及考勤表一并落到前端可视化。所有数值由确定性引擎计算（铁律 1），身份来自 JWT 登录态（铁律 2），
> 查询在数据层带租户过滤（铁律 3）。
> **2026-11-24 复核**：`information_schema` 实查为 **54 张** BASE TABLE（本文 53 为 2026-11-16 快照，保留不改）；`db/*.sql` 的 MySQL 建表脚本共定义 56 张，其中 `notification_tables.sql` 的 2 张推送表（学生推送订阅/学生推送投递）尚未在本库执行；DuckDB 另有 3 张（学生特征/岗位特征/推荐日志）。

## 二、「校园行为洞察」新板块专节

路由：学生端 `/student/campus`，教师端 `/teacher/campus`。
数值全部由 `engine/campus_insight.py` 确定性计算并返回结构化结果（铁律 1：LLM 只组织表达，不产数）；
`student_id`/`teacher_id` 由 FastAPI 从 JWT 解析注入（铁律 2）；所有 SQL 在数据层带 `tenant_id` 过滤，
教师查学生走 `_fetch_student`（租户 + 任教范围校验，铁律 3）。

### 学生端看点（只看本人）

| 看点 | 数据表 | 呈现形式 |
|---|---|---|
| 学习投入画像 `study_style` | 图书馆记录 + 消费记录 + 考勤 + 学生活动 | 引擎判定的投入风格标签 + 依据数值 |
| 到馆/借阅趋势 | 图书馆记录 | 学期粒度到馆次数、借阅册数折线 |
| 消费规律性 | 消费记录 | 规律性 = 活跃天数/120、日均金额卡片 |
| 出勤率 | 考勤 | 出勤率学期趋势折线 |
| 证书/竞赛/项目 | 学生活动 | 三类堆叠柱状图 + 最近获得清单 |
| 岗位兴趣信号 | 岗位浏览日志 | 浏览/收藏聚合的意向城市 TOP、意向行业 TOP |
| 周快照时间线 | 周快照 | 周度红/黄/绿三色判定时间线 |
| 事实卡 | 学生扩展信息 | 四六级、政治面貌、意向城市、每周学时 |

### 教师端看点（只看任教班级聚合）

| 看点 | 数据表 | 呈现形式 |
|---|---|---|
| 班级投入画像分布 | 上述行为表聚合 | 班内 `study_style` 分布柱状图 |
| 低投入名单 `low_engagement` | 消费/考勤/图书馆等 | 引擎确定性规则判定的名单 + 命中规则明细（规则与阈值集中在 engine/campus_insight.py，可审计、不由模型裁定） |

| 班级兴趣城市 TOP | 岗位浏览日志 | 班级聚合意向城市排行 |

## 三、覆盖结论

- 本次盘点共 **53 张表，全部有明确用途**：学业、职业规划就业、校园行为、通知知识四大主题直接服务
  学生学业/职业规划/就业主线；主数据表承担鉴权、租户隔离与任教范围校验底座。
- 运维类表（审计日志、抓取运行日志、面试题库导入日志、智能体记忆、宠物记忆/长期记忆）以
  **质量看板（AgentQuality.vue）、同步健康度与后台形式**呈现，不强行做学生可视化。
- 本轮「校园行为洞察」补齐了最后 6 张无产品板块的表（图书馆记录、消费记录、学生活动、
  岗位浏览日志、周快照、学生扩展信息），并让考勤从纯后台特征升级为前端趋势图；
  至此不存在「只造数、无用途」的表。
