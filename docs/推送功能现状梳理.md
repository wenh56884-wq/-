> 编制：小帆（数据与文档负责人）
> 编制日期：2026-11-22
> 范围：通读 `app/` 与 `engine/` 现有通知体系，为「浏览器 Web Push」接入做前期梳理

> 实证口径：所有链路均给出 `文件:行号`，可在本仓库复核；前端展示部分由后端接口契约推断（`web/` 归阿衡，未读其实现）

---

## 0. 结论速览（TL;DR）

1. **现有通知是「拉模型」不是「推模型」**：前端轮询 `GET /student/notices`，用「编号 > 已读水位」判未读；服务端不主动推。
2. **两条通知源共用一个水位**：竞赛通知（抓取落库）+ 考证三阶段提醒（实时计算、不落库），合并进同一个未读列表。
3. **另有一条独立通知子系统**：学校通知 / 通知匹配（career 模块，`GET /career/notices`），**未并入**上述通知中心。
4. **Web Push 基础设施为零**：全仓库无订阅表、无 Service Worker、无 VAPID、无 `pywebpush`（已 grep 确认）。
5. **最大硬约束**：公网演示站是 **HTTP**（`http://101.34.254.115/`），而 Web Push / Service Worker 要求 **HTTPS 安全上下文**——当前部署**做不了** Web Push，须先上域名 + HTTPS（与麦克风受限同源，见面试契约 §23.4）。

## 1. 现有通知的完整链路（谁产生 → 存哪张表 → 怎么拉取 → 前端怎么展示）

### 1.1 链路总览

```
[产生]                      [存储]                 [拉取]                    [展示]
竞赛: competition_sync 守护线程 ──> 竞赛通知 表 ─┐
                                                ├─> engine.competition.unread_notices
考证: cert_guide.active_reminders(实时算,无表) ─┘         │  (编号 > 学生通知已读.已读通知编号)
                                                          │  + cert_guide.merge_notices 合并
                                                          ▼
                                              tools.my_notices (身份取自 JWT)
                                                          ▼
                                              GET /student/notices  ──> 前端通知中心: 未读角标 + 列表
                                              POST /student/notices/read ──> mark_read 推水位
```

### 1.2 竞赛通知链路

- **谁产生**：`app/competition_sync.py` 后台守护线程。FastAPI 启动时 `start_background_sync()`（`competition_sync.py:68`）拉起，间隔 `COMPETITION_SYNC_MINUTES`（默认 1440=每天，0=关闭，`:25`）。每轮 `sync_once()`（`:33`）复用 `scripts/seed_competition.fetch_notices/save_notices` 抓重庆财经学院教务处「学科竞赛」栏目，**只写官方原文标题/日期/链接，抓不到就跳过不编造**；以 `(标题,发布日期)` 唯一键幂等，新增才落库并写审计 `competition.sync`。
- **存哪张表**：`竞赛通知`（`db/competition_tables.sql:26`）

  | 字段 | 类型 | 说明 |
  |---|---|---|
  | 编号 | BIGINT AI PK | 自增 id，**未读判定基准** |
  | 标题 | VARCHAR(300) | 官方原文 |
  | 发布日期 | VARCHAR(16) | 官方原文（字符串，非 DATE） |
  | 链接 | VARCHAR(300) | 原文链接，抓不到回落栏目页 |
  | 来源 | VARCHAR(64) | 默认 `cfec-jwc` |
  | 抓取时间 | TIMESTAMP | 入库时间 |

  唯一键 `uk_notice_title_date(标题,发布日期)`。
- **怎么拉取**：`engine/competition.py:187 unread_notices(student_no, tenant_id, limit)`——先读该生水位，再 `SELECT ... FROM 竞赛通知 WHERE 编号 > 水位 ORDER BY 发布日期 DESC, 编号 DESC LIMIT`，统计未读数，最后调 `cert_guide.merge_notices` 并入考证提醒。
- **水位表**：`学生通知已读`（`db/competition_tables.sql:39`）

  | 字段 | 类型 | 说明 |
  |---|---|---|
  | 编号 | BIGINT AI PK | |
  | 学号 | VARCHAR(32) | 本租户内唯一 |
  | 租户编号 | INT | 默认 1，**多租户隔离键** |
  | 已读通知编号 | BIGINT | **水位点**（判未读用），默认 0 |
  | 最后已读时间 | DATETIME | 仅展示用 |
  | 更新时间 | TIMESTAMP | 自动更新 |

  唯一键 `uk_student_read(租户编号,学号)`。**设计要点**：用自增 id 而非时间戳（DATETIME 秒级精度会漏同秒新通知）；每人只存一个水位点，不给每人复制通知，学生再多不写爆。
- **推水位**：`engine/competition.py:224 mark_read`——水位 = `max(MAX(竞赛通知.编号), cert_guide.watermark_max())`，upsert 回 `学生通知已读`。之后的新通知才会再提醒。

### 1.3 考证三阶段提醒链路

- **谁产生**：`engine/cert_guide.py:308 active_reminders(today)` **实时计算，不落任何提醒表**。遍历 `考证目录`，按 `cert_status` 生成三类提醒：

  | 阶段常量 | 值 | 触发条件 |
  |---|---|---|
  | `PHASE_UPCOMING` | 0 | 未开始且距报名开通 ≤14 天 |
  | `PHASE_ENROLL` | 1 | 报名中 |
  | `PHASE_EXAM` | 2 | 临近考试（0 ≤ 距考试 ≤14 天） |

  阈值 `REMIND_EXAM_DAYS=14`（`:30`）。提醒 **id = `CERT_ID_OFFSET`(10⁹, `:29`) + 编号×100 + 阶段**，恒大于竞赛通知 id；阶段推进 → id 增大 → 已读后下一阶段仍会再提醒。
- **存哪张表**：提醒本身**无表**，事实源是 `考证目录`（`db/cert_tables.sql:10`，关键字段：编号/考证名称/报名官网/报名开始/报名截止/考试开始/考试日期/核实日期/来源链接）。每条带官方来源 + 核实日期，未公布日期标「预计」。
- **怎么合并**：`cert_guide.py:381 merge_notices(competition_items, watermark, today, limit)`——取 id > 水位的考证提醒，与竞赛通知合并、按 id 倒序、截断 limit，返回 `items` + `cert_unread_cnt`（考证未读数单独计，不占竞赛计数）。
- **水位陷阱**：`cert_guide.py:370 watermark_max()` 无活跃提醒时**必须返回 0**，不能返回偏移量——否则 mark_read 会把水位推到 10⁹，误将所有竞赛通知标已读。

### 1.4 工具层 + REST 接口（前端通知中心接口）

- **工具层**：`agents/tools.py:1435 my_notices(ctx, limit)` / `:1444 mark_notices_read(ctx)`——身份只取自 `ctx`（JWT 注入），`_require_student(self)` + `_resolve_self`，**无学号入参**（铁律 2）；返回附 `tools_version`。
- **REST 签名**（`app/routers/student.py`，prefix `/student`，`_guard` 把 PermissionError→403 / ValueError→422）：

  | 方法 路径 | 鉴权 | 入参 | 返回 |
  |---|---|---|---|
  | `GET /student/notices` (`:74`) | `require_student` | `limit` Query 默认 20（1..50） | `{student_no, last_notice_id, last_read_at, unread_cnt, items[], tools_version}` |
  | `POST /student/notices/read` (`:81`) | `require_student` | 无 | `{student_no, last_notice_id, marked:true}` |

  `items[]` 两种形状：竞赛 `{id,title,published_at,url,source,fetched_at}`；考证 `{id,kind:"cert",cert_id,phase,title,content,url,published_at,source:"cert"}`。
- **前端怎么展示**（由接口契约推断，`web/` 实现归阿衡）：通知中心（铃铛/通知卡）**轮询** `GET /student/notices`，用 `unread_cnt` 渲染未读角标，`items` 渲染通知列表（标题 + 官方链接，点击跳原文）；用户点「已读」调 `POST /student/notices/read` 推水位。**本质是客户端定时拉取，服务端无主动推送通道。**

### 1.5 学校通知 / 通知匹配（独立子系统，未并入通知中心）

- `学校通知`（`db/career_tables.sql:121`）：编号/租户编号/标题/发布单位/截止日期 DATE/摘要/链接/分类/原始哈希(md5 唯一)/发布日期。来源 `scripts/import_notice.py` CSV 导入。
- `通知匹配`（`:144`）：通知编号 FK × 学生编号 FK，相关度 high/medium/low + 理由（≤30 字），唯一键 `(通知编号,学生编号)`。**模型判相关性，截止状态由引擎给**。
- 接口：`GET /career/notices`（`app/routers/career.py:200`，`require_student`）→ `nodes.filter_notices`，**已截止的在代码里剔除，模型看不到**。
- **与通知中心的关系**：这是 career 模块的另一条通知路径，**不走** `学生通知已读` 水位、**未并入** `/student/notices`。做 Web Push 时要决定是否把它也纳入触发源（见 §3.4）。

### 1.6 现有实时通道盘点

- 全仓库**唯一**的服务器推流是 **chat 的 SSE**（`app/routers/chat.py:67 stream_chat`，`StreamingResponse` + `_sse`），仅用于对话流式输出。
- **通知没有任何 SSE / WebSocket**，纯轮询。→ Web Push 对启航是一条**全新通道**，不是改造现有推流。

## 2. 要做「浏览器 Web Push」还缺什么

> 已 grep 确认：`vapid / webpush / pywebpush / PushSubscription / serviceWorker` 全仓库 **0 命中**。下列全部从零建。

### 2.1 缺口总表

| 缺口 | 现状 | 需新建 | 归属 |
|---|---|---|---|
| 推送订阅表 | 无 | `推送订阅`（+可选 `推送日志`）DDL | 深蓝 |
| Service Worker | 无 | `push-sw.js`（push / notificationclick / pushsubscriptionchange） | 阿衡 |
| VAPID 密钥 | 无 | 生成 + `.env` 管理 + 公钥下发接口 | 深蓝 |
| 权限引导 | 无 | `Notification.requestPermission` 时机与 UI | 阿衡 |
| 发送服务 | 无 | `pywebpush`（或 cryptography+httpx 手搓）+ 触发钩子 | 深蓝 |
| 依赖 | `cryptography==50.0.2`、`httpx==0.28.1` 已有；**无 pywebpush** | `requirements.txt` 加 `pywebpush`（锁版本） | 深蓝 |
| **HTTPS** | **公网 HTTP，不支持** | 域名 + 证书（或 localhost 演示） | 主控/运维 |

### 2.2 订阅表字段（浏览器 PushSubscription 落库）

浏览器 `pushManager.subscribe()` 返回 `{endpoint, keys:{p256dh, auth}}`，须存：
- `endpoint`：推送服务 URL（Mozilla/Google 等），**可能很长（>500 字符）→ 用 TEXT**；另存 `endpoint_hash`（sha256）做幂等唯一键。
- `p256dh`：客户端 ECDH 公钥（base64url，约 88 字符）。
- `auth`：认证密钥（base64url，约 24 字符）。
- 绑定身份：`学号 + 租户编号`（**取自 JWT，不接受入参指定他人**，铁律 2/3）。
- 运维字段：设备标签（UA）、状态（active/revoked/expired）、失效原因（410/404/手动退订）、最后推送时间。
- 一个学生可多设备/多浏览器 → 多条订阅，唯一键落在 `endpoint_hash`，不是学号。

### 2.3 Service Worker 需要什么接口（阿衡，契约）

SW 独立文件（如 `web/public/push-sw.js`，注册在站点根 scope），需三个事件监听：
1. **`push`**：`event.data.json()` 取 payload → `self.registration.showNotification(title, {body, icon, badge, tag, data:{url}})`。`tag` 用于去重/折叠同类通知。
2. **`notificationclick`**：`notification.close()` → `clients.openWindow(data.url)` 或聚焦已开客户端（跳到对应板块，如 `/student/opportunity`）。
3. **`pushsubscriptionchange`**：浏览器可能轮换 endpoint → 重新 `subscribe` 并 `POST /push/subscribe` 更新落库。

主页面侧：`navigator.serviceWorker.register('/push-sw.js')` → `Notification.requestPermission()`（**须用户手势**）→ `registration.pushManager.subscribe({userVisibleOnly:true, applicationServerKey: urlBase64ToUint8Array(VAPID公钥)})` → 把 subscription `POST /push/subscribe`。
**SW 注册与 Push 都要求安全上下文（HTTPS 或 localhost）**。

### 2.4 VAPID 密钥管理（深蓝）

- VAPID 是一对 ECDSA（P-256）密钥 + 一个 `subject`（`mailto:` 联系邮箱）。**公钥给前端**（`applicationServerKey`），**私钥仅后端签名用**。
- 生成：`pywebpush` 自带 vapid 工具，或用已有 `cryptography` 生成 EC 密钥。
- 存储（铁律 6）：`VAPID_PRIVATE_KEY` / `VAPID_PUBLIC_KEY` / `VAPID_SUBJECT` 只放 `.env`，代码用 `os.getenv`/pydantic-settings 读；`.env.example` 标 `REPLACE_ME`；**私钥绝不入 git、绝不硬编码**。
- 下发：`GET /push/vapid-public-key` 只回公钥 + subject（公钥本就公开）。

### 2.5 权限引导时机（阿衡）

- **不要页面加载即弹**（浏览器会拦截/降权，且骚扰）。应在**用户明确动作**时请求：通知中心放「开启桌面提醒」按钮，登录后、用户已见到未读通知价值时再引导。
- 按 `Notification.permission` 分支：`granted`→直接 subscribe；`denied`→提示「已被浏览器拒绝，需到站点设置手动开启」（**无法再弹**）；`default`→显示引导按钮。
- 与现有通知中心 UI 融合（阿衡自有 `web/`）；HTTP 环境隐藏按钮并提示「需 HTTPS」（照麦克风 §23 降级范式）。

### 2.6 发送侧（深蓝）

- 库：推荐 `pywebpush.webpush(subscription_info, data, vapid_private_key, vapid_claims)`；底层复用已有 `cryptography`/`httpx` 亦可手搓。
- 触发源：竞赛同步新增（`sync_once` added>0）、考证阶段推进（见 §3.4）。
- 失败治理：推送服务回 **404/410** → 订阅已失效，标 `expired` 并清理；设 TTL / urgency；按 `tag` 去重避免轰炸。
- 内容铁律 1：payload 里的**数字必须来自 engine**（竞赛/考证事实），不经 LLM 生成。

### 2.7 硬约束与风险（必须先拍板）

1. **HTTPS 是前置条件**：当前公网 `http://101.34.254.115/` 无法注册 SW / 订阅 Push。要么上域名 + HTTPS，要么只在 localhost 演示。**这一条不解决，Web Push 无从落地。**
2. **浏览器兼容**：Chrome/Edge/Firefox 桌面可用；Safari 需 macOS 16+ / iOS 16.4+ 且「添加到主屏幕」的 Web App 才支持，iOS 浏览器内不支持。
3. **隐私**：学生数据敏感（项目已有「隐私走本地模型」倾向）。payload **最小化**——只发标题 + 通用正文 + 跳转 url，**不发完整成绩/个人明细**；订阅经第三方推送服务（Mozilla/Google），需知悉 endpoint 外发。
4. **多租户/身份**：订阅绑定 `租户编号+学号`，发送按租户过滤（铁律 3）。
5. **频率治理**：复用「编号 > 水位」语义，只推真正新增；避免与现有未读角标重复打扰。

### 3.2 后端接口签名（深蓝）

| 方法 路径 | 鉴权 | 入参 | 返回 | 说明 |
|---|---|---|---|---|
| `GET /push/vapid-public-key` | 公开只读 | 无 | `{public_key, subject}` | 公钥本就公开，供前端 subscribe |
| `POST /push/subscribe` | `require_student` | `{endpoint, keys:{p256dh,auth}, device_label?}` | `{subscription_id, status}` | upsert 绑定 ctx 学号+租户；**无学号入参** |
| `POST /push/unsubscribe` | `require_student` | `{endpoint}` 或 `{subscription_id}` | `{ok:true}` | 标 revoked / 删除 |
| `GET /push/subscriptions/me` | `require_student` | 无 | `{items:[{subscription_id,设备标签,状态,创建时间,最后推送时间}]}` | 可选，本人订阅管理/调试 |

内部能力（非 HTTP）：
- `engine/push.py send_to_student(student_no, tenant_id, payload) -> dict`：遍历该生 active 订阅 → `pywebpush.webpush` → 404/410 标 expired；写 `推送日志`。`payload={title, body, url, tag, kind, notice_id}`，数字直引 engine。
- 依赖：`requirements.txt` 加 `pywebpush==<锁定版本>`；VAPID 三件套从 `.env` 读（§2.4）。
- 路由挂载 + 身份注入沿用 `app/auth.require_student` / `ToolContext`，错误经 `_guard` 同口径。

### 3.3 前端对接契约（阿衡，仅契约不含代码，`web/` 归阿衡）

1. 新增 SW 文件 `web/public/push-sw.js`（根 scope），实现 §2.3 三事件。
2. 通知中心加「开启桌面提醒」入口：注册 SW → 用户手势触发 `requestPermission` → `pushManager.subscribe(applicationServerKey=VAPID公钥)` → `POST /push/subscribe`。
3. `notificationclick` 跳转 url 落到对应板块（竞赛/考证 → 机会库，学校通知 → 对应页）。
4. 权限三态 UI（granted/denied/default）+ **HTTP 降级提示**（照麦克风 §23 范式）。
5. 退订入口 → `POST /push/unsubscribe`。
6. 现有轮询 `GET /student/notices` 与未读角标**保留**（Web Push 是补充通道，不替代站内未读）。

### 3.4 触发源接入点（深蓝）

| 触发源 | 接入点 | 推送对象 | 备注 |
|---|---|---|---|
| 竞赛新通知 | `competition_sync.sync_once` added>0 | 全体订阅学生（广播） | 复用竞赛 id；payload 带官方链接 |
| 考证阶段推进 | 定时任务比对 `active_reminders` 阶段变化 | 订阅学生（可按 `适合标签` 定向） | id=10⁹+编号×100+阶段，阶段升才推 |
| 学校通知（可选） | `通知匹配` 新增 high 相关 | 对应学生 | 需先决定是否纳入（§1.5） |

去重：按 `tag`（如 `comp-<id>` / `cert-<编号>-<阶段>`）折叠；只推「编号 > 该生水位」的真正新增，避免与站内角标重复。

### 3.5 验收清单

- [ ] 订阅入库：subscribe 后 `推送订阅` 有该生记录，endpoint_hash 幂等（重复订阅不新增）。
- [ ] 推送到达：触发源新增 → 浏览器收到系统通知（HTTPS/localhost）。
- [ ] 点击跳转：notificationclick 落到正确板块。
- [ ] 退订清理：unsubscribe 后不再收到。
- [ ] 失效清理：404/410 → 状态 expired，不再尝试。
- [ ] HTTP 降级：HTTP 站隐藏入口 + 提示，不报错。
- [ ] 身份/租户：伪造学号入参无效；跨租户不推送（铁律 2/3）。
- [ ] 数值一致：payload 数字与 engine 一致（铁律 1）。

### 3.6 分工与边界

- **深蓝（后端）**：`db/push_tables.sql`、`engine/push.py`、`app/routers/push.py`、`requirements.txt`、`.env.example`、触发钩子。
