# 目录说明

> 本文件随项目演进持续维护；文件清单以当前实现与 `git ls-files` 为准。
> 机器可读原则：**看目录就知道该改哪个文件**。任何新文件都必须落在下表某个目录内，不得随意新建顶层目录。

| 目录 | 职责 | 允许出现的文件 | 禁止事项 |
|---|---|---|---|
| `app\` | FastAPI 网关层：HTTP 入口、认证、路由、请求校验 | `main.py` `auth.py` `audit.py` `schemas.py` `config.py` | ❌ 不写业务算法；❌ 不直接写 SQL 查询分析数据（走 `engine\store.py`） |
| `app\routers\` | 按角色拆分的接口 | `teacher.py` `student.py` `career.py` | ❌ 不从请求体读取 `student_id`（只能从 JWT 注入） |
| `app\static\` | 静态资源 | css / js / 图片 | ❌ 不放数据文件 |
| `web\` | Vue 3 + Vite + ECharts 前端（演示界面） | `index.html` `vite.config.js` `package.json`；`src\`：`main.js` `App.vue` `router\` `api\http.js` `layout\` `components\` `composables\` `views\`（Login / TeacherDashboard / TeacherStudents / StudentHome / AgentChat） | ❌ 不直连 MySQL/DuckDB（只走 `/api`）；❌ `node_modules\` `dist\` 不入 git；❌ 不做数值计算（数值全部来自接口） |
| `agents\` | LangGraph 多智能体层：编排、工具、审核 | `llm.py` `graph.py` `tools.py` `teacher_agent.py` `student_agent.py` `critic.py`；`career\`（职业规划 5 节点） | ❌ 不在 Agent 内做数值计算；❌ 不让模型直接产出分数；❌ 不让模型判门槛/判色/算日期 |
| `engine\` | 确定性引擎：预警 / 画像 / 推荐 / 规划规则 / 存储抽象 | `store.py` `rules.py` `warning.py` `profile.py` `recommend.py` `career_rules.py`（career-v1）`career_guide.py`（年级分层生涯规划） | ❌ 不 import `agents\`（禁止反向依赖）；❌ 不调用大模型 |
| `rules\` | 业务规则库（**数据，不是代码**）：考公 / 考研 / 就业模板 | `kaogong.json` `kaoyan.json` `jiuye.json` | ❌ 不放 Python 代码；❌ 不改结构（改结构须同步 `tests\test_career_rules.py`）；❌ 阶段占比之和必须为 1 |
| `db\` | 建表 SQL（结构唯一来源） | `mysql_schema.sql` `source_tables_v2.sql`（4 张行为/兴趣源表）`career_tables.sql`（7 张职业规划表）`elective_tables.sql`（选修课表）`duckdb_schema.sql` | ❌ 不写数据（数据由 `scripts\seed_mock.py` 生成） |
| `etl\` | 数据接入、清洗、脱敏、校情参照 | `__init__.py` `mask.py` `clean_jobs.py` `school_cqufe.py` | ❌ 不把真实姓名/身份证落到任何日志；❌ 不改 `school_cqufe.py` 的学院/专业（只能对照培养方案补课程） |
| `scripts\` | 一次性运维脚本 | `init_db.py` `seed_mock.py` `seed_freshman.py` `seed_activity.py` `seed_elective.py` `load_jobs.py` `build_profile_raw.py` `build_web.ps1` `smoke_test.ps1` `gen_verify_report.py` `init_qihang.ps1` | ❌ 不 import `app\`（脚本必须能脱离服务独立跑） |
| `tests\` | pytest 用例，与 `engine\` / `agents\` 模块一一对应 | `test_warning.py` `test_profile.py` `test_profile_raw.py` `test_metric_consistency.py` `test_tools.py` `test_api.py` `test_critic.py` `test_recommend.py` `test_career_rules.py` `test_career_pipeline.py` `test_career_guide.py` | ❌ 纯引擎用例不连真实数据库（用内存 DuckDB / mock）；`test_api.py` 等集成用例无 MySQL 时自动 skip |
| `data\` | 运行期数据 | `raw\`（真实岗位原始 CSV，只读）`cleaned\`（ETL 产物）`analytics.duckdb` `hidden_risk.csv` | ❌ 不入 git（已 ignore）；❌ `raw\` 内文件不得修改 |
| `docs\` | 交付文档 | `目录说明.md` `数据来源说明.md` **`指标口径字典.md`（唯一事实来源）** `VERIFY.md` `演示脚本.md` `答辩PPT大纲.md` | ❌ 不写代码；❌ 改指标前不改口径字典 = 违规 |
| `logs\` | critic 审核日志、运行日志 | `critic_YYYYMMDD.log` 等 | ❌ 不入 git（已 ignore），不写密钥与个人信息 |

## 依赖方向（单向，不可逆）

```
app\  ──▶ agents\  ──▶ engine\  ──▶ db\(schema) / data\
 │                        ▲
 └────────────────────────┘      （app 可直接调 engine，跳过 agents）
scripts\ tests\  ──▶ 可依赖任意层，但不得被任何层依赖
```

出现「`engine\` import `agents\`」或「`agents\` 里写 SQL 算分数」，即为架构违规，必须打回重做。

## 新增文件的落位判据

1. 涉及 HTTP / 鉴权 / 序列化 → `app\`
2. 涉及提示词 / 模型调用 / 状态机 / 工具注册 → `agents\`
3. 涉及分数 / 阈值 / 规则 / 统计口径 → `engine\`
4. 涉及表结构 → `db\`
5. 一次性的初始化 / 造数 / 校验 / 报告 → `scripts\`
6. 验证某函数行为 → `tests\`
7. 涉及页面 / 图表 / 交互 → `web\src\`（数据一律走 `src\api\http.js`）
8. 涉及**业务规则数值**（门槛、达标线、阶段占比、时间节点）→ `rules\*.json`，**不要写进 `.py`**，也不要写进提示词
