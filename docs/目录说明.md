# 目录说明

> 本文件由建目录脚本阶段一并生成，P1-1 阶段可让 CodeBuddy 在此基础上补充实现细节。
> 机器可读原则：**看目录就知道该改哪个文件**。任何新文件都必须落在下表某个目录内，不得随意新建顶层目录。

| 目录 | 职责 | 允许出现的文件 | 禁止事项 |
|---|---|---|---|
| `app\` | FastAPI 网关层：HTTP 入口、认证、路由、请求校验 | `main.py` `auth.py` `audit.py` `schemas.py` `config.py` `demo_streamlit.py` | ❌ 不写业务算法；❌ 不直接写 SQL 查询分析数据（走 `engine\store.py`） |
| `app\routers\` | 按角色拆分的接口 | `teacher.py` `student.py` | ❌ 不从请求体读取 `student_id`（只能从 JWT 注入） |
| `app\static\` | 演示页静态资源 | css / js / 图片 | ❌ 不放数据文件 |
| `agents\` | LangGraph 多智能体层：编排、工具、审核 | `llm.py` `graph.py` `tools.py` `teacher_agent.py` `student_agent.py` `critic.py` | ❌ 不在 Agent 内做数值计算；❌ 不让模型直接产出分数 |
| `engine\` | 确定性引擎：预警 / 画像 / 推荐 / 存储抽象 | `store.py` `rules.py` `warning.py` `profile.py` `recommend.py` | ❌ 不 import `agents\`（禁止反向依赖）；❌ 不调用大模型 |
| `db\` | 建表 SQL（结构唯一来源） | `mysql_schema.sql` `duckdb_schema.sql` | ❌ 不写数据（数据由 `scripts\seed_mock.py` 生成） |
| `etl\` | 数据接入、清洗、脱敏、校情参照 | `__init__.py` `mask.py` `clean_jobs.py` `school_cqufe.py` | ❌ 不把真实姓名/身份证落到任何日志；❌ 不改 `school_cqufe.py` 的学院/专业（只能对照培养方案补课程） |
| `scripts\` | 一次性运维脚本 | `init_db.py` `seed_mock.py` `smoke_test.ps1` `gen_verify_report.py` `init_qihang.ps1` | ❌ 不 import `app\`（脚本必须能脱离服务独立跑） |
| `tests\` | pytest 用例，与 `engine\` / `agents\` 模块一一对应 | `test_warning.py` `test_profile.py` `test_tools.py` `test_api.py` `test_critic.py` `test_recommend.py` | ❌ 不连真实数据库（用内存 DuckDB / mock） |
| `data\` | 运行期数据 | `raw\`（真实岗位原始 CSV，只读）`cleaned\`（ETL 产物）`analytics.duckdb` `hidden_risk.csv` | ❌ 不入 git（已 ignore）；❌ `raw\` 内文件不得修改 |
| `docs\` | 交付文档 | `目录说明.md` `VERIFY.md` `演示脚本.md` `答辩PPT大纲.md` | ❌ 不写代码 |
| `logs\` | critic 审核日志、运行日志 | `critic_YYYYMMDD.log` 等 | ❌ 不入 git（已 ignore），不写密钥与个人信息 |

## 依赖方向（单向，不可逆）

```
app\  ──▶ agents\  ──▶ engine\  ──▶ db\(schema) / data\
 │                        ▲
 └────────────────────────┘      （app 可直接调 engine，跳过 agents）
scripts\ tests\  ──▶ 可依赖任意层，但不得被任何层依赖
```

出现「`engine\` import `agents\`」或「`agents\` 里写 SQL 算分数」，即为架构违规，必须打回重做。

## 新增文件的落位判据

1. 涉及 HTTP / 鉴权 / 序列化 → `app\`
2. 涉及提示词 / 模型调用 / 状态机 / 工具注册 → `agents\`
3. 涉及分数 / 阈值 / 规则 / 统计口径 → `engine\`
4. 涉及表结构 → `db\`
5. 一次性的初始化 / 造数 / 校验 / 报告 → `scripts\`
6. 验证某函数行为 → `tests\`
