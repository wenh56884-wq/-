# 启航系统｜面试实验室创新功能契约 v1

> 本文件是**唯一契约来源**。前端、后端引擎、路由三侧并行开发，一律以此为准；
> 任何字段变更必须先改本文件。所有新代码不修改 `app/routers/interview.py` 既有行为。

## 0. 命名与约束（硬性）

- Python：类型注解齐全，注释用中文；模块顶部写"职责/铁律"注释块，风格对齐 `engine/interview.py`。
- 版本号常量：`PANEL_VERSION = "panel-v1"` / `EXPRESSION_VERSION = "expr-v1"` /
  `PASSPORT_VERSION = "passport-v1"` / `SHADOW_VERSION = "shadow-v1"`。
- **分数一律确定性计算**（纯函数、无随机、无模型参与）。模型只允许组织语言，且必须可降级。
- 生产环境模型可能超时：任何 LLM 调用必须有 `try/except` 模板降级，绝不因模型抖动 500。
- 中文标点、UTF-8；代码里的引号必须是 ASCII 直引号。
- 不得新增数据库表、不得改已有表结构。只读 `面试会话` / `面试问答` / `简历*`。

## 1. 已有数据事实（不要猜）

`面试问答` 每行：`轮次`、`问题类型`、`问题`、`学生回答`（NULL=跳过）、`点评`、`评分`、`点评版本`。
`面试会话` 每行：`编号`、`学生编号`、`岗位名称`、`岗位要求快照`(JSON: title/skill_tags/education/industry/city/pool)、
`状态`(ongoing/finished/abandoned)、`提纲`(JSON 数组：`{round,type,question,rubric?,probe_of?}`)、
`当前轮次`、`最大轮次`、`总分`、`报告`、`差距清单`、`引擎版本`、`创建时间`、`完成时间`。

单题评分 `engine.interview.score_answer()` 返回：
`{score:0~100, keyword_score:0~30, keyword_hits[], keyword_missed[], struct_score:0~25, struct_marks[],
depth_score:0~25, length, evidence_score:0~20}`。

四维原始满分：内容 30 / 结构 25 / 深度 25 / 证据 20。

## 2. `engine/panel.py` — 圆桌三面试官

```python
PANEL_VERSION = "panel-v1"

PANELISTS = [
    {"id": "tech",     "name": "陈工", "title": "技术面", "tagline": "只看你能不能落地",
     "weights": {"content": 0.46, "structure": 0.24, "depth": 0.18, "evidence": 0.12}, "bias": -1.5},
    {"id": "hr",       "name": "李敏", "title": "HR 面", "tagline": "看你是否值得长期投入",
     "weights": {"content": 0.18, "structure": 0.34, "depth": 0.16, "evidence": 0.32}, "bias": +2.0},
    {"id": "pressure", "name": "周总", "title": "压力面", "tagline": "专挑你话里的空洞",
     "weights": {"content": 0.40, "structure": 0.18, "depth": 0.30, "evidence": 0.12}, "bias": -4.0},
]

def dimension_percent(item: dict) -> dict:
    """把 score_answer 明细折算成四维百分制：content/struct/depth/evidence (0~100, 2位小数)。"""

def review(scores: list[dict | None], outline: list[dict], job_skills: list[str] | None = None) -> dict:
    """三视角独立打分 + 共识。纯函数。

    返回：
    {
      "version": "panel-v1",
      "panelists": [
        {"id","name","title","tagline","score": 73.4, "verdict": "推荐|待定|不通过",
         "level": "稳|边缘|危险", "delta_vs_consensus": -2.1,
         "focus": "技术深度",            # 该面试官最在意、且本场最弱的一维
         "comment": "……",              # 60~110 字，按模板拼装，引用真实命中/漏掉的要点
         "highlights": ["…"],          # ≤3 条，来自 keyword_hits / 结构标记
         "concerns": ["…"],            # ≤3 条，来自 keyword_missed / 低分维度
         "rounds": [{"round":1,"score":68.2}]   # 该视角下逐轮分，未答为 null
        }, ...  # 恰好 3 个，顺序 tech/hr/pressure
      ],
      "consensus": {"score": 74.1, "spread": 9.3, "level": "高度一致|分歧可控|分歧明显|严重分歧",
                    "verdict": "推荐|待定|不通过", "summary": "…", "advice": ["…","…"]},
      "divergence": {"dimension": "evidence", "gap": 12.4, "note": "…"} | None,
      "answered": 5, "skipped": 1
    }
    """

def panel_prompt_facts(result: dict) -> str:
    """把 review() 结果压成一段 ≤600 字的事实清单，供路由层交给模型写「合议总结」。
    必须逐字列出分数，模型不得改数。"""
```

规则：
- 每个 persona 分 = Σ(权重×对应维度百分制) + bias，clamp 到 `[0,100]`，保留 1 位小数。
- `verdict`：≥78 推荐，≥62 待定，否则不通过。`level`：≥75 稳，≥60 边缘，否则危险。
- `spread` = 三人最高分 − 最低分（1 位小数）。
  `level`：<5 高度一致；<12 分歧可控；<20 分歧明显；否则严重分歧。
- `divergence`：取三人分差贡献最大的维度（按 `|权重差| × 维度分` 估算），`gap` 为该维度的
  最高-最低加权贡献差（1 位小数）；三人分差 <5 时返回 None。
- `summary` 与 `advice` 是**模板**生成（不调模型），advice 给 2~3 条可执行动作，
  必须点名具体维度与具体漏掉的要点。

## 3. `engine/expression.py` — 表达力度量

```python
EXPRESSION_VERSION = "expr-v1"
FILLERS = ("嗯", "呃", "那个", "就是", "然后就是", "这个", "对吧", "其实", "怎么说")

def analyze(text: str, duration_sec: float | None = None,
            segments: list[dict] | None = None) -> dict:
    """表达力度量。segments = [{"text": str, "start": float, "end": float}]，可空。

    返回：
    {
      "version": "expr-v1",
      "score": 78,                 # 0~100 整数；duration_sec 缺失时按文本指标给分
      "confidence": "high|low",    # 有 duration 且 >=5s → high，否则 low
      "chars": 236, "duration_sec": 68.0,
      "speed_cpm": 208,            # 字/分钟，duration 缺失为 null
      "speed_band": "偏快|标准|偏慢|未知",
      "filler_total": 3, "filler_rate": 0.013, "fillers": {"嗯": 2, "那个": 1},
      "avg_sentence_len": 23.6, "max_sentence_len": 48,
      "pause_count": 4, "longest_pause_sec": 2.4, "pause_ratio": 0.12,
      "metrics": [{"key":"speed","label":"语速","value":"208 字/分","score":82,
                   "hint":"面试舒适区 200~260 字/分"}, ...],   # 4~5 条
      "tips": ["…", "…"]           # 2~3 条，具体可改
    }
    """
```

评分规则（满分 100，扣分制，最低 0）：
- 语速：有 duration 时按 200~260 为最佳区；`<150` 或 `>320` 扣 18，边缘扣 8。无 duration 不扣。
- 填充词：`filler_rate = filler_total / max(1, chars/100)`（每百字填充词数），
  `<=0.5` 不扣，`<=1.5` 扣 8，`<=3` 扣 15，否则扣 24。
- 句长：`avg_sentence_len` 在 15~45 不扣；`>60` 扣 10（长句难跟）；`<10` 扣 6（碎片化）。
- 停顿：有 segments 时，间隔 `>1.2s` 记一次停顿；`pause_ratio>0.25` 扣 10，`>0.4` 扣 18。
- 结构词：出现"首先/其次/最后/第一/第二/因此/所以/举个例子"任一 +4（上限 100）。
- `speed_band`：<170 偏慢，170~320 标准，>320 偏快。

TARGET_DEFAULT = {"content": 78, "structure": 76, "depth": 72, "evidence": 70}

                 "target":78,"gap":4.0,"hit":false}, ...],   # 固定 4 维，顺序 content/structure/depth/evidence
      "trend": [{"date":"2026-11-10","total":71.2,"job_title":"…","session_id":12}],
      "growth": {"delta": 6.4, "first_total": 65.0, "last_total": 71.4,
                 "best_dim": "structure", "worst_dim": "evidence",
                 "consistency": 0.72},   # consistency = 1 - 归一化波动，0~1
      "next_action": {"dim": "evidence", "label": "证据支撑", "gap": 6.4,

- 维度百分制与 panel 一致（`dimension_percent` 复用 `engine.panel` 的实现，不要重复写）。

- `badges` 固定 5 个，未达成 `earned:false`：`first`（≥1 场）、`streak3`（≥3 场）、

## 6. 路由 `app/routers/interview_lab.py`

`router = APIRouter(prefix="/interview/lab", tags=["interview-lab"])`，全部 `Depends(require_student)`，
只能访问本人数据（`ctx.student_id`），越权一律 404（不泄露存在性）。

| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| GET | `/panel/{sid}` | — | `{"session_id","job_title","panel": review() 结果, "job_skills":[...]}` |
| GET | `/shadow/{sid}` | — | `{"session_id","items":[{"round","label","question","answer","shadow": shadow() }]}` |
| POST | `/expression` | `{"text","duration_sec"?,"segments"?}` | `analyze()` 结果 |
| GET | `/passport` | `?target=` 可空 | `build_passport()` 结果 |
| GET | `/report-card/{sid}` | — | `{"session_id","job_title","date","total","grade","panel","passport_dot","probe_chain","top_problems","next_actions","expression"}` |

`report-card` 的 `probe_chain`：
`[{"round":3,"label":"项目深挖","question":"…","score":62.0,"is_probe":true,"probe_of":2,"gap":"漏掉：…"}]`
（`probe_of` 来自提纲里的 `probe_of` 字段；没有则 null）

`grade`：≥85 `A`，≥75 `B+`，≥65 `B`，≥55 `C+`，否则 `C`。
`expression`：该场若前端提交过表达力结果则返回，否则 `null`（本期不做持久化，先恒为 null）。

错误：会话不存在/不属于本人 → 404；会话未完成 → 409（`detail` 中文）；引擎算不出（全未答）→ 200 但
`consensus.score` 为 null，前端要能兜住。

## 8. `engine/attribution.py` — 失分溯源到课程

**为什么市面没有**：商业面试产品只有「表达分」，拿不到学生的课程与成绩；
启航能把「漏掉的考点」反查到「哪门课、多少分、专业内什么位次」，从而把
「你不会说」和「你没学扎实」分开——这是诊断分型，不是打分。

```python
ATTRIBUTION_VERSION = "attribution-v1"

def attribute(missed_by_round: dict[int, list[str]],
              courses: list[dict],
              cohort_stats: dict[str, dict] | None = None) -> dict:
    """courses: [{"course_id":int,"name":str,"credit":float,"score":float,
                  "percentile":float|None}]   # percentile=该课在同专业同年级的分位(0~100)
       cohort_stats: {course_name: {"mean":..,"p25":..,"p75":..,"n":..}} 可空
    """
```

返回：
```json
{
  "version": "attribution-v1",
  "type": "foundation|expression|mixed|unknown",
  "type_label": "基础薄弱型|表达组织型|混合型|证据不足",
  "missed_share_weak": 0.62,
  "items": [{"concept":"数据治理","course":"大数据治理","course_id":12,
             "score":68.0,"percentile":32.0,"credit":3.0,
             "rounds":[3,5],"verdict":"课程基础薄弱",
             "evidence":"第3、5轮都漏掉了这个考点"}],
  "unmatched": ["…"],
  "soft_skipped": 5,
  "narrative": "两三句话把结论说透，点名课程与轮次",
  "actions": [{"when":"本周","what":"重学《大数据治理》第3章","why":"两轮追问都漏这个考点"}]
}
```

算法（确定性，纯函数）：
1. 考点归一：复用 `engine.interview._norm`；课程名同样归一。
2. 匹配（两级）：
   - **技能桥（强）**：课程若通过 `engine.kg.skills_for_course()` 培养了该考点对应的技能，
     即命中该课程。这一级解决「数据治理」对不上「数据仓库与ETL」这类字面不重合的情况。
   - **字面（弱）**：考点与课程名的 2-gram 覆盖率 ≥ 0.5 视为命中。
   多个命中取 `credit` 大者，同 credit 取覆盖率高者。匹配不到进 `unmatched`（不硬凑）。
2.1 **软性要点不参与课程归因**：`兴趣/项目/学习方法/沟通/团队/压力/动机/规划…` 等
   动机与自我表达类要点记入 `soft_skipped`，既不匹配课程也不进 `unmatched`。
   **若失分全部是软性要点，分型判为 `expression`（不是 `unknown`）**——这类失分与成绩无关，
   结论必须是「表达组织问题」，不能拿「证据不足」糊弄。
3. `verdict`：`percentile<40` 或 `score<70` → 课程基础薄弱；`<60` → 课程掌握一般；
   否则 `课程掌握良好`；`percentile is None` 时只按分数判。
4. `missed_share_weak`：落在「薄弱课程」上的**考点条目数** / 已匹配条目数（3 位小数）。
5. 分型：无可匹配条目 → `unknown`；`>=0.6` → `foundation`；`<=0.25` → `expression`；否则 `mixed`。
6. `narrative` 模板按分型给不同结论，必须包含具体课程名与轮次，禁止套话。
7. `actions` 2~3 条，`when` ∈ {本周, 两周内, 本学期}，按薄弱程度排序。

## 9. `engine/peer.py` — 同辈分位基准

**为什么市面没有**：商业产品只给绝对分（"你 74 分"无意义）；高校有同专业同年级的
完整成绩母体，才能给「你在同辈里的位置」，且样本不足时诚实降级为课程代理基准。

```python
PEER_VERSION = "peer-v1"

def percentile_of(value: float, samples: list[float]) -> float:
    """严格小于的比例 ×100，保留 1 位；samples 为空返回 None。"""

def benchmark(total: float | None, dims: dict[str, float],
              samples: list[float], cohort_size: int,
              proxy: dict[str, list[float]] | None = None) -> dict:
    """samples=本专业同年级已练面试的 total 列表；proxy={dim_key: 该维度相关课程分数列表}"""
```

返回：
```json
{"version":"peer-v1","basis":"observed|course_proxy|none",
 "cohort":128,"sample_n":12,
 "total":{"score":74.1,"percentile":77.0,"rank":29,"label":"前 23%"},
 "dims":[{"key":"content","label":"内容","score":74.0,"percentile":62.0,"basis":"observed"}],
 "note":"基于本专业同年级 12 场实测样本",
 "honest":true}
```
规则：`sample_n>=5` → `observed`；否则若 proxy 有数据 → `course_proxy`
（`note` 明确写「样本不足 5 场，改用课程成绩代理基准，非面试实测」）；都没有 → `basis="none"`，
`percentile` 全为 null。`label`：percentile≥90「前 10%」，≥75「前 25%」，≥50「中上」，
≥25「中下」，否则「后 25%」。`rank = ceil((1-p/100)*cohort)`，最小 1。

## 10. `engine/group.py` — 无领导小组讨论（群面）模拟

**为什么市面没有**：所有 AI 面试产品都是 1v1；而无领导小组讨论是国内校招**特有**环节，
学生最怕、最缺练习机会。这里做「学生 + 3 个 AI 候选人」的四方抢话局。

```python
GROUP_VERSION = "group-v1"
CANDIDATES = [

  {"id":"spark","name":"王锐","role":"搅局者","tagline":"专问‘凭什么’","color":"#fb923c"},
]

def make_topic(job_title: str, industry: str | None, skills: list[str]) -> dict
def opening(topic: dict) -> dict
def ai_turn(state: dict, candidate_id: str, speak=None) -> dict
def student_turn(state: dict, text: str) -> dict
def evaluate(state: dict) -> dict
```

状态字典（前端与后端共同持有，JSON 可序列化）：
```json
{"version":"group-v1","topic":{"title","brief","keywords":["…"],"minutes":12},
 "turns":[{"idx":1,"speaker":"ice|data|spark|student","name":"…","text":"…","at":0}],
 "student_turns":[1],"elapsed_turns":6}
```

`evaluate()` 返回：
```json
{"version":"group-v1",
 "role":{"id":"leader|contributor|follower|silent","label":"推动者|贡献者|跟随者|沉默者","reason":"…"},
 "metrics":{"talk_ratio":0.28,"chars":236,"new_points":3,"converge_marks":1,
            "first_speak_position":0.33,"question_asked":1,"interrupted":0},
 "scores":{"contribution":72,"collaboration":65,"structure":70,"overall":69},
 "highlights":["…"],"improvements":["…"],"next_drill":"一句可立刻练的动作",
 "transcript_digest":[{"speaker":"student","gist":"…"}]}
```

评估规则（确定性）：
- `talk_ratio` = 学生字数 / 全部字数（3 位小数）。
- `new_points`：学生发言里出现的议题 `keywords` 中，**此前无人说过**的个数。
- `converge_marks`：命中 `("总结","归纳","共识","建议我们","综上","分三步","统一")` 的次数。
- 角色：`talk_ratio>=0.3 且 new_points>=2` → leader；`talk_ratio>=0.15 且 new_points>=1` → contributor；
  `talk_ratio>=0.08` → follower；否则 silent。
- 四个分数由上述指标线性映射，clamp 0~100，`overall` 为加权和（贡献 .35 / 协作 .25 / 结构 .25 / 表达 .15）。
- `speak(system, user) -> str` 可注入；默认 `agents.llm.generate_reply`，异常或空返回时回落到
  `CANDIDATE_FALLBACK` 模板句（每个角色 3 句轮换），保证离线可演示。

## 13. `engine/readiness.py` — 岗位就绪度（从成绩单到简历的证据链）

**为什么市面没有**：招聘平台的「匹配度」只能读简历自述，它不知道你《数据库原理》考了 88 分；
学校的教务系统知道你考了多少分，但不知道岗位要什么。启航两边都有，所以能回答一个
商业产品回答不了的问题：**"我明明学过、也考得不错，为什么简历上看起来什么都不会？"**

`engine/recommend.py` 的 `skill_cover_of` 只算「覆盖了几项」，本模块要算**每项技能的证据等级**。

```python
READINESS_VERSION = "readiness-v1"

STATUS_LABELS: dict[str, str] = {
    "proven":  "有成绩单背书",
    "hidden":  "被埋没的资产",
    "claimed": "只有自述，没有成绩支撑",
    "weak":    "学过，但没学牢",
    "gap":     "完全空白",
}
STATUS_WEIGHTS: dict[str, float] = {
    "proven": 1.0, "hidden": 0.72, "claimed": 0.45, "weak": 0.35, "gap": 0.0,
}

def skill_match(skill: str, course_name: str) -> float:
    """技能 × 课程名 的匹配度 0~1（纯函数，确定性）。"""

def find_courses_for_skill(skill: str, catalog: Sequence[str]) -> list[str]:
    """课程库反查：哪些课培养这项技能（复用 engine.kg.skills_for_course）。"""

def assess(job: Mapping[str, Any], courses: Sequence[Mapping[str, Any]],
           resume_text: str, catalog: Sequence[str] | None = None) -> dict:
    """job: {"title":str,"industry":str|None,"skills":[str,...]}
       courses: [{"name":str,"score":float|None,"credit":float|None,"percentile":float|None}]
       catalog: 学校开设的全部课程名（用于给空白技能找补课路径），可为空
    """
```

**匹配规则（技能 ↔ 课程，取最高分匹配的那门课）**
1. 归一化复用 `engine.interview._norm`。
2. 课程培养技能集 = `engine.kg.skills_for_course(course_name)`。若其中任一技能与岗位技能：相等、
   或双向包含且两边都 ≥2 字 → 记 1.0。
3. 否则用 2-gram 覆盖率 `cov(skill, course_name)`，`cov ≥ 0.5` → 记 `cov`（最高 0.9，避免与精确命中并列）。
4. 多门课命中取匹配度高者；同匹配度取 `credit` 大者；再同取 `score` 高者。

**技能 ↔ 简历**：`in_resume = True` 当且仅当技能（归一后）出现在 `_norm(resume_text)` 中，
或该技能 2-gram 覆盖率 ≥ 0.5 且技能长度 ≥3。**短技能（<2 字）只认精确包含**，不许瞎匹配。

**状态判定**

| 有命中课程 | 成绩 | 简历有写 | status |
|---|---|---|---|
| 是 | `score >= 70` | 是 | `proven` |
| 是 | `score >= 70` | 否 | **`hidden`** |
| 是 | `score < 70` | 任意 | `weak` |
| 是 | `None`（无成绩记录） | 是 | `claimed` |
| 是 | `None` | 否 | `gap` |
| 否 | — | 是 | `claimed` |
| 否 | — | 否 | `gap` |

**返回结构**

```json
{
  "version": "readiness-v1",
  "job_title": "数据分析师",
  "industry": "互联网",
  "readiness": 63.4,
  "level": "high|mid|low|critical",
  "level_label": "够投|能投但需补说法|缺口明显|一轮游",
  "counts": {"proven": 3, "hidden": 2, "claimed": 1, "weak": 1, "gap": 2},
  "items": [
    {"skill": "SQL", "status": "proven", "status_label": "有成绩单背书",
     "course": "数据库原理", "score": 88.0, "percentile": 76.0, "credit": 4.0,
     "match": 1.0, "in_resume": true,
     "evidence": "《数据库原理》88 分，专业前 24%"}
  ],
  "hidden_assets": [
    {"skill": "统计分析", "course": "概率论与数理统计", "score": 92.0, "percentile": 88.0,
     "why": "岗位要求统计分析，你这门课 92 分（专业前 12%），但简历里一个字没提",
     "suggestion": "在简历「技能」栏加一行：统计分析（《概率论与数理统计》92 分，专业前 12%）"}
  ],
  "gaps": [
    {"skill": "Hive", "fix": "先修/重学《大数据技术》第 4 章",
     "how": "course", "courses": ["大数据技术"]}
  ],
  "interview_hooks": [
    "你在《数据库原理》里学过 SQL，说一个你写过的慢查询和优化过程。"
  ],
  "narrative": "两三句话：点名技能与课程，说清最该补的一件事，禁止套话。",
  "advice": [{"when": "本周", "what": "...", "why": "..."}]
}
```

**计算规则**
- `readiness = round(100 * Σ(w[status]) / n_items, 1)`；`n_items == 0` → `readiness = None`，`level = "unknown"`。
- `level`：`>=80 high`、`>=65 mid`、`>=45 low`、`else critical`。
- `counts` 五键齐全（缺失记 0），顺序固定 proven/hidden/claimed/weak/gap。
- `hidden_assets`：`status == "hidden"` 的条目，按 `score` 降序，最多 4 条。
- `gaps`：`status in ("gap","claimed")` 的条目。`how` 为 `course` 当且仅当 `find_courses_for_skill`
  在 catalog 里找到课程；否则 `course` 也允许为空列表、`how = "self"`，`fix` 换成方向性一句
  （如「先补 Hive 基础语法与分区表，用公开数据集跑通一次 ETL」），**不许编造课程名**。
- `interview_hooks`：从 `proven` + `hidden` 里按 `score` 降序取前 3 条（不足则少给），
  模板句必须带入课程名与该课培养的技能。
- `narrative` 按 `level` 给不同结论，**必须点名至少一项具体技能和一门具体课程**。
  `critical` 时不许说"加油"，要说清差在哪几项上。
- `advice` 2~3 条，`when ∈ {本周, 两周内, 本学期}`。

## 14. `engine/calibration.py` — 面试官视角（评分校准）

**为什么市面没有**：所有 AI 面试产品都让你**被**面。但真正让人答题变准的，是当一次面试官——
你会立刻看清「什么答案听起来好、什么答案其实什么都没说」。这是教育学里的同伴评价（peer
assessment）与评分元认知训练，商业面试产品的商业模型（卖课时）里根本没有这一环。

**做法**：拿一道真实题库题目（含 rubric），构造 3 位模拟候选人的作答，**不告诉学生谁是谁**，
让他排序；再揭晓引擎标准分与他的偏差，诊断他的评判偏误。

```python
CALIBRATION_VERSION = "calibration-v1"

PERSONAS: tuple[dict[str, str], ...] = (
    {"id": "talker", "label": "话术型", "hint": "结构漂亮，但把要点全绕开了"},
    {"id": "doer",   "label": "实干型", "hint": "要点踩得准，却不会包装"},
    {"id": "vague",  "label": "空转型", "hint": "两句说完，没有信息量"},
)

def build_candidates(question: str, rubric: Mapping[str, Any]) -> list[dict]:
    """返回三位候选人的作答：[{"id":"talker","answer":str}...]，顺序固定 talker/doer/vague。"""

def score_candidates(candidates: Sequence[Mapping], rubric: Mapping,
                     evidence: Sequence[str]) -> list[dict]:
    """用 engine.interview.score_answer 算标准分，返回带 standard / dims 的列表。"""

def judge(picks: Sequence[Mapping], candidates: Sequence[Mapping]) -> dict:
    """picks: [{"id":"talker","rank":1}]，rank ∈ {1,2,3} 且同一题内互不重复。
       candidates 为 score_candidates 的输出（含 standard 与 standard_rank）。
    """
```

**`build_candidates` 生成规则（确定性、无模型、无随机）**
- 取 `rubric["keywords"]`（1~6 个）与 `rubric["struct_marks"]`（通常为「首先/其次/最后/第一/第二/结果/…」）。
- `talker`：**故意只用结构标记 + 通用套话，一个 rubric 关键词都不出现**。长度 110~180 字。
  模板：「这个问题我分三层看。首先，要{d1}；其次，{d2}；最后，{d3}。总的来说，{d4}，我有信心做好。」
  `d1..d4` 从固定的通用短语池按题目 hash 取（**不能用 random**，用 `hashlib.md5(question)` 的字节取模）。
- `doer`：**把 rubric 关键词自然嵌进去**，给具体动作与数字，结构标记只用 1~2 个。长度 100~160 字。
  模板：「这块我们真做过。当时{kw1}那段最卡，我先{kw2}，再把{kw3}补上，用{kw4}做了一次全量校验，
  两周收口，返工率从 30% 降到 8%。」
  关键词不足 4 个时循环取用；**一个关键词都没有**（无 rubric 的题型）→ 退化为具体动作描述，不含空泛词。
- `vague`：40~60 字。「这个我觉得按流程来就行，先把事情做完，遇到问题再调整，整体上问题不大。」
- 三条答案都不许出现「作为一个 AI」「候选人」这类自指词；不许 markdown。

**`judge` 计算规则**
- 每题内：`standard_rank` = 按 `standard` 降序（并列按 talker<doer<vague 顺序稳定）。
- `accuracy = round(100 * (1 - mean(|my_rank - standard_rank|) / 2), 1)`；无有效 pick → `accuracy = None`。
- `level`：`>=85` → `sharp`「判断很准」；`>=65` → `fair`「大体靠得住」；否则 `blunt`「还需要练眼力」。
- 偏误诊断（每题都算，累加计数）：
  - `talker_bias`：`talker` 的 `my_rank < standard_rank` → 计数 +（差几档就加几）。
  - `doer_bias`：`doer` 的 `my_rank > standard_rank` → 同上。
  - `harsh` / `lenient`：`my_rank` 与 `standard_rank` 的平均偏差方向，只在不构成上面两种偏误时统计。
- `biases` 输出命中项（`weight > 0` 才算），每项 `{key,label,detail,tip}`，`detail` 必须引用具体答案片段。
- `insights` 2~3 条，按 `level` 与 `biases` 组合给不同结论，**必须引用具体题目或具体原话片段**。
- `next_drill` 一句可立刻做的动作（如「把你上一场面试的第 2 题答案重写：删掉所有形容词，只留动作和数字」）。

**返回结构**

```json
{
  "version": "calibration-v1",
  "accuracy": 78.3,
  "level": "sharp|fair|blunt",
  "level_label": "判断很准",
  "items": [
    {"round": 2, "question": "……",
     "candidates": [
       {"id": "talker", "label": "话术型", "answer": "……",
        "standard": 42.1, "standard_rank": 3, "my_rank": 1,
        "dims": {"keyword_score": 0.0, "struct_score": 17.0,
                 "depth_score": 22.5, "evidence_score": 3.2},
        "revealed": true}
     ],
     "verdict": "你把话术型排到了第一：它结构齐全，但 0 个要点命中。"}
  ],
  "biases": [{"key": "talker_bias", "label": "结构偏好",
              "detail": "两处都把「分三点讲」当成内容扎实，但它一个要点都没踩到。",
              "tip": "先听要点，再看结构：结构只是包装。"}],
  "insights": ["……", "……"],
  "next_drill": "……"
}
```

**边界**：`picks` 为空 / 长度不足 → 只返回 `accuracy=None` 与 `insights=["还没排序，没有可校准的判断。"]`，
`items` 里每项的 `my_rank` 为 `null`、`revealed` 为 `true`；不得抛异常。同一题内 rank 重复 → 视为无效，
该项 `my_rank` 记 `null` 且不影响其它题。

## 18. `readiness` 的两处实现澄清

### 18.1 `/readiness/jobs` 按「与你课程的匹配度」排序

初版按 `编号 DESC` 取 20 个岗位，点开第一个就是「国企银行坐班」这类完全不对口的岗位，
演示第一屏直接是「一轮游」，功能再好也白搭。现在：

1. 首次请求把全部带技能标签的岗位（2560 行）解析进进程内存，TTL 10 分钟，实测 0.08s / 命中后 0.046s；
   早期只扫最近 200 行不够——那 200 行恰好全是银行客服岗，排序等于没排。
2. `match_hint = 命中技能数 / 岗位技能数`，其中「命中」指岗位技能与
   `skills_for_course(该生已修课程)` 的技能集双向包含（短词不参与）。
3. 排序键 `(match_hint, 命中数, -job_id)` 降序，`q` 关键词在内存里过滤。

`items[]` 因此多一个 `match_hint` 字段（0~1，两位小数），前端可用来做排序提示。

### 18.2 分位文案：满分不许说「专业前 0%」

`100 - percentile` 直接拼字符串会出两种离谱说法：满分 → 「专业前 0%」，垫底 → 「专业前 90%」。
统一口径（后端 `_top_txt` 与前端 `pctText` 必须一致）：

| percentile | 文案 |
|---|---|
| ≥ 95 | 专业前列 |
| 50 ~ 95 | 专业前 {100-p}% |
| < 50 | 专业后 {100-p}% |

**这条同样适用于前端**：早期前端在「被埋没的资产」卡片上自己又算了一遍 `100 - p` 并钳位到 1，
导致后端已改成「专业前列」、页面仍显示「专业前 1%」。任何分位文案只允许有一处实现。

## 19. `calibration` 的两处实现澄清

### 19.1 三条答案的长度是设计指标，不是随意写的

`engine.interview.score_answer` 的深度分档以 **120 字**为界（<30→0、<120→0.6、其余→1.0）。
所以：

- `talker` 控制在 **104~119 字**：结构标记塞满（结构分 25 满分）、深度分只拿 15、要点 0 命中。
  这正是现实里那种「听着挺像样，回头一想什么都没说」的人。若让它也超过 120 字，
  talker 与 doer 的分差会缩到 10 分以内，"你被话术骗了"这个结论就站不住。
- `doer` 控制在 **130~169 字**：关键词全塞（30 满分）、深度满分（25）、只带 1 个结构标记（10）。
- 实测分差：**talker ≈ 41 / doer ≈ 69 / vague ≈ 15**，差 28 分，足以让排序有明确对错。
- 长度差允许到 80 字。不再为了"防靠长度猜"而把 talker 拉长——长度分档本身就是引擎设计，
  抹平它等于把教学效果一起抹掉。

### 19.2 选题按「硬关键词数」排序，不按轮次顺序

真实题库的 rubric 关键词分三类，只有一类能做教学素材：

| 类型 | 例子 | 能不能用 |
|---|---|---|
| 硬知识 | 机器学习、过拟合、数据漂移、基线 | ✅ 首选 |
| 软性 | 兴趣、项目、学习方法、团队 | ⚠️ 塞进「当时{词}那块最卡」会变病句 |
| 结构词 | 背景、负责、难点、方案、结果 | ❌ 与 struct_marks 重合，talker/doer 无法区分 |

所以 `_calibration_pool` 按 `_hard_keyword_count(rubric)` 降序取前 3 题，实测自动跳过
「为什么选这个方向」（软性）与「讲一个项目」（结构词），选中「过拟合成因」「线上效果下降怎么排查」
「准确率 60% 被队友质疑」——全是能讲干货的题。

`doer` 的句式也随之定稿：`当时{术语}那块最卡，我先把{术语2}从头理了一遍…`。
这个句式只对术语成立，是选题策略和模板设计必须配套的原因。

## 21. 导出接口的 `fields` 参数（自选字段）

四个导出接口（`/export/students`、`/export/grades`、`/export/student-grades/{no}`、`/export/my-grades`）
均新增 `fields` 查询参数：

- 留空 → 全字段，输出与旧版逐列一致（**向后兼容**）。
- `fields=a,b,c` → 只输出这三列；列序按字段目录顺序，不按传入顺序。
- 未知 key → `422`，`detail` 里列出不认识的字段（不静默丢列）。
- 字段目录：`GET /export/fields?dataset=students|grades|student-grades|my-grades`，
  返回 `groups`（分组）与 `fields`（扁平，带 `group`），角色不匹配返回 `403`，未知数据集 `404`。
- 成绩类导出勾了字段时，Excel 不再附「个人汇总」sheet，JSON 的 `summary` 为空数组——
  勾了三列却多出一张八列汇总，等于没尊重用户的选择。

## 22. 工作流审批的读模型（2026-11-18）

三个接口只读、不改审批语义，目的是把「学生发起 → 教师裁决 → 学生回看」闭合：

| 接口 | 角色 | 用途 | 关键字段 |
|---|---|---|---|
| `GET /workflow/approvals/pending` | 教师 | 待审单 | `steps[]`（提交快照的执行顺序，含 `tool/label/title/on_error`）、`definition_changed`、`inputs` |
| `GET /workflow/approvals/history` | 教师 | 已处理回查 | `action`、`comment`、`status`、`approver_name`、`decided_at` |
| `GET /workflow/my-runs` | 学生本人 | 我的申请 | `status_text`、`steps[]`、`decided{action,comment,decided_at}`、`error` |

铁律：

1. `steps` 一律取自**提交快照**（没有快照才回退定义表），审批的就是学生当时看到的那份流程。
2. `pending` 状态下 `my-runs` 的 `steps` 恒为空数组——一步都没跑，不能展示成「执行了但没有结果」。
3. `my-runs` 的 `student_id` 只来自 JWT，**不接受任何入参指定他人**。
4. 三个接口都不触发执行、不写库（只读），执行仍只发生在 `POST /workflow/runs/{id}/decide`。

## 23. 群面语音模式（2026-11-18 夜）

群面由「纯文字聊天」升级为「会议室能听见人说话」。实现放在
`web/src/composables/useVoice.js`，**后端零改动、零密钥、零费用**，全部走浏览器原生 Web Speech API。

### 23.1 两种能力、两套降级

| 能力 | 技术 | 触发 | 不可用时 |
|---|---|---|---|
| AI 候选人开口 | `speechSynthesis` | 每有新 AI 发言自动朗读，主持人开场白也读 | `ttsReady=false` → 隐藏「播报」按钮，纯文字照常 |
| 学生语音发言 | `SpeechRecognition`（zh-CN） | 点「语音发言」连续识别，文字实时写入输入框 | `sttSupported=false` → 隐藏麦克风按钮，显示降级提示 |

**能力互相独立**：朗读在 HTTP 站也能响（不要求安全上下文）；语音输入要求
`SpeechRecognition` 存在 **且** `window.isSecureContext === true`（HTTPS 或 localhost）。
线上 `http://101.34.254.115/` 只有朗读、没有麦克风——这是浏览器硬限制，不是没实现。

### 23.2 音色档位（`VOICE_PROFILES`）

| speaker id | 人物 | pitch | rate |
|---|---|---|---|
| `ice` | 林一（破冰者） | 1.15 | 1.05 |
| `data` | 赵敏（数据派） | 1.45 | 1.0 |
| `spark` | 王锐（搅局者） | 0.75 | 1.12 |
| `host` / `moderator` / `system` | 主持人 | 1.0 | 0.98 |

读完即取 `getVoices()` 里的 zh-CN 音色并缓存（Chrome 的 voices 异步加载，挂了
`voiceschanged`）；`SpeechRecognition` 的 `continuous=true` + `onend` 自动续录，
用户不点停止就一直开着（Chrome 单段约 60 秒会自动结束）。

### 23.3 四条交互铁律

1. **发言即停播**：点「语音发言」先 `cancel()` 掉正在朗读的 AI，否则麦克风把 AI 的声音当你的发言。
2. **发言/结束/切走即停录**：点「发言」「听他们说一轮」「结束并评估」都会先 `stopListen()`，已识别文本留在输入框。
3. **朗读去重**：`spokenKeys`（按 turn key）+ `spokenTexts`（按文本）双集合。开场白并入
   `state.turns` 时 key 会从 `opening` 变成 `turn-N`，只靠 key 会重读一遍。
4. **一次只读一条**：新一批发言到达时清空未读队列再排队，保证「谁刚说完就读谁」，
   不积压成十几秒的旧语音。

前端细节：正文气泡加 `.speaking` 高亮 + 「播报中」标签；聆听态黄色脉冲提示条；
`prefers-reduced-motion` 下关闭脉冲动画。朗读另有兜底定时器（`4000 + 字数×90ms`，
封顶 30s）——无声卡/headless 环境里 `onend` 可能永不触发，否则「播报中」会永久卡住。

### 23.4 演示环境怎么开麦克风

公网 HTTP 站想现场演示语音输入，用 Chrome/Edge 的「按安全源对待」开关：

```
chrome.exe --unsafely-treat-insecure-origin-as-secure=http://101.34.254.115 ^
           --user-data-dir=C:/temp/qh-demo
```

实测（headed Chromium + 该开关）：`window.isSecureContext === true`，麦克风按钮出现、
聆听态正常、控制台 0 错误。headless 模式该开关不生效，别用它做验收。
长期方案仍是上域名 + HTTPS。

### 23.5 修订（同晚，用户反馈）：只读候选人 + 音色择优

用户反馈两点：声音难听、不要"面试官的语音"。修订：

1. **朗读白名单 `SPOKEN_SPEAKERS = ['ice','data','spark']`**：主持人/议题（开场白）一律不读，
   `speakTurns` 入口直接过滤，GroupRoom 里开场播报代码删除。只有三位 AI 候选人开口。
2. **音色池择优，不再单音色靠变调硬凑**：`refreshVoicePool()` 把系统全部 zh 音色按
   质量打分排序（name 含 natural/neural/online/google 加分，zh-CN 优先）；
   每位候选人按偏好序列挑不同音色——林一 Xiaoyi、赵敏 Xiaoxiao、王锐 Yunxi 优先，
   命中即用，都不可用退回池首。pitch/rate 只留轻微差异（1.0 上下 ±0.08）。
   用 **Edge 浏览器**打开会有"Microsoft Xiaoxiao/Yunxi Online (Natural)"自然音色，
   Chrome 只有桌面 SAPI 音色（相对机械）——演示建议用 Edge。
3. 每次朗读前 `refreshVoicePool()`：voices 是异步加载的，晚到的自然音色也能被下一句用上。

## 24. 冷场提示：AI 宠物递抓手（2026-11-18 深夜）

学生卡住时，AI 宠物（小航）在气泡里给一句**结构化提示**——不代替思考、不给答案，
只递「从哪个角度开口」。实现：`web/src/composables/useIdleHint.js` +
`usePet.js` 新增模块级 `petSay(text)`。

### 24.1 触发规则

| 场景 | 静默阈值 | 每轮上限 | 触发时机 |
|---|---|---|---|
| 1v1 面试（InterviewRoom） | 45 秒未动笔 | 2 条/题 | 题目出现即计时；打字/提交/换题重启 |
| 群面（GroupRoom） | 60 秒未接话 | 2 条/场 | 进入 live 即计时；打字/发言/听完 AI 一轮重启 |

- 学生一有动作（`watch(answerText)` / `watch(draft)` / 提交成功 / AI 说完一句）都 `poke()` 重新计时，
  不会在他正在组织语言时冒话。
- `pick(count)` 返回 `null` 表示此刻不适合说话（正在提交、AI 正在发言），本次跳过、不自动续期。

### 24.2 文案策略：按题型/局面给抓手，不给答案

- 1v1 按题型分组（motivation / major / project / scenario / stress / counter / general），
  例如 project → 「套 STAR：目标、你的动作、可验证的结果，最后补一句复盘」。
- 群面按局面分组：**还没开口** → 抢框架/复述成判断的破冰句；**已开口** → 收敛分歧、
  给折中方案、点名推进；**倒计时归零** → 「主动收尾：共识一句、分歧一句、下一步一句」。
- 全部确定性模板，**不发模型请求**：提示必须 1 秒内出现，不能比学生还慢；同一题内按
  `count` 轮换，不重复同一句。

### 24.3 与宠物的边界

- `petSay` 在宠物「专注模式」（`focusMode=true`）或未登录（`available=false`）时直接返回 false，
  不打断专注、不写脏气泡。
- 气泡沿用 `PetBubble` 的打字机 + 自动消失，隐藏后 `App.vue` 会 `clearBubble`，同一句能再次触发。
- 冷场提示不写库、不记分、不进评估——它只是陪伴，学生跳过照样正常出分。

## 25. 群面议题轮换（2026-11-19 凌晨）

用户反馈「每次群面都是同一种问答」。根因：议题模板只有 4 个且按岗位名「字符求和取模」
确定选取——同一岗位永远命中同一道模板；关键词也固定取 TOPIC_UNIVERSAL 前三个。

修订（`engine/group.py` + 路由 `group_start`）：

1. **模板扩到 12 种不同题型**：项目排期取舍 / 需求冲突处理 / 培养预算分配 / 方案评审分歧 /
   数据口径之争 / 突发应对 / 跨部门协作冲突 / 渠道取舍 / 复盘改进 / 招聘标准之争 /
   定价决策 / 上线决策。不再全是「资源分配」一类。
2. **`make_topic(..., seed=0)`**：模板序号 = (岗位名求和 + seed) % 12；
   通用关键词池按 `seed % len(TOPIC_UNIVERSAL)` 轮转起点。路由层每次开局传
   `random.randrange(1<<20)`——同一岗位每场题型大概率不同（12 选 1，连开 4 场
   撞题概率 ≈ 5%）。**seed 固定 → 议题完全相同**，引擎「可复现」铁律与既有测试不破。
3. 回归：test_group_engine 21 + interview_pool 17 + workflow_flow 5 + export_fields 11
   = 54 passed；公网实测同一岗位连开 4 场命中 3 种不同题型。

## 26. 个性化模拟面试：结合岗位库与历史问答（2026-11-19 凌晨）

用户要求「继续优化模拟面试和面试实验室，结合岗位库和问答简历里面的东西」。
此前 1v1 出题只看「岗位 × 简历」，**同一岗位同一简历永远同一套题**（模板永远取
第 0 条变体、题库重排是确定性的）。本次把「历史问答」（`面试会话.提纲` +
`面试问答.评分`）引入出题链路。

### 26.1 个性化三件套（`interview_start`，引擎 `build_outline` 新增三参数）

| 能力 | 数据来源 | 行为 |
|---|---|---|
| 跨场次防重复 | 近 3 场已完成会话的提纲里 `source.kind='bank'` 的题库题编号 | `_bank_pick` 直接跳过这些题，抽下一道 |
| 弱点靶向 | 最近一场有评分的面试，按题型求平均分，最低且 <70 | 该题型被裁剪时换回提纲；题面加前缀「上次模拟面试你在「X」类题只得 N 分，本题重点考察：」 |
| 模板变体轮换 | 历史会话总数 | 模板题按 `variant % len(变体)` 取，不再永远第 0 条 |

- 参数取不到时全部按默认值走（`exclude=set()`、`weak=None`、`variant=0`），
  **首次面试/历史缺失不报错，行为与旧版完全一致**。
- seed/variant 固定 → 提纲可复现（引擎铁律不破）；三个新参数均有单测
  （`test_outline_template_variant_rotates` / `test_outline_weak_type_gets_anchor_and_kept` /
  `test_outline_bank_exclude_skips_used_ids`，题库未加载时后者自动跳过）。
- 返回体新增 `personalized: {avoided_recent, weak:{type,score}, weak_label}`，前端条件渲染徽标。

### 26.2 实验室联动

`GET /interview/lab/summary` 的 `next_steps` 里「最近一场最弱的是…」步骤改为
**直达靶向面试**（`tab: practice`，cta「开一场靶向面试」，why 说明会重点考察最弱
题型并避开近 3 场做过的题）——实验室发现弱点 → 一键开一场针对它的面试，闭环。

### 26.3 前端

`InterviewRoom.vue` 题卡加个性化条：`已避开你近 3 场做过的题`（avoided_recent>0）
与 `重点考察X（上次 N 分）`（weak 存在）两个徽标，条件渲染——没有历史就不显示，
不假装个性化。

## 27. 考证中心：目录 + 个性化推荐 + 三阶段提醒（2026-11-19）

用户要求考证推荐「真实有效、适合学生」，且要讲清谁考什么、差什么、能获得什么、
什么时候开始/结束、如何报名，AI 要给提示并说明为什么，提醒可进通知消息。

### 27.1 三层结构

| 层 | 实现 | 铁律 |
|---|---|---|
| 目录 | `考证目录` 表（8 条种子），字段含主办方/报名窗口/考试日期/周期/费用/报名方式/官网/收益/前提 + **依据公告链接 + 核实日期** | 只放能核对的官方信息；官方未公布的标「预计」并写明推算依据，缺失不冒充 |
| 推荐 | `engine/cert_guide.recommend`：级别 + 状态 + 去向 + 专业 + 年级五维打分，输出 `match_reasons` / `gaps` | 理由必须可解释到具体事实（专业、年级、目标、截止天数），不做无依据断言 |
| 提醒 | `active_reminders` 三阶段（即将报名≤14天 / 报名中 / 考前≤14天），`id = 10^9 + 编号×100 + 阶段` | 与竞赛通知共用水位；阶段推进时 id 增大 → 会再提醒一次；无提醒时 `watermark_max=0`，绝不污染竞赛通知已读 |

### 27.2 接口与工具

- `GET /cert/list`（公开只读，`cert_catalog`）、`GET /cert/recommend`（学生 JWT）。
- `tools.cert_guide` / `tools.cert_catalog` → `student_agent` 关键词 → `graph.py`
  分发 + 模板渲染（`match_reasons` 逐条、`gaps` 首条醒目、附官网与公告链接）
  → `auto_plan` 工具描述，四处同步（项目契约：新增工具三处登记，渲染另算）。
- 路由守卫：`证书` 命中后排除 `毕业证/简历/技能证书/荣誉证书/证书领取/管理办法/
  规定/制度/细则/实施办法`——制度问法必须让给 `kb_search`。
