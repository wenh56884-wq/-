# 启航「创新全景」板块设计方案

> 本文职责：定义「创新全景」板块的产品/技术方案、信息架构与挂载位置。
> 本文不做什么：不提供实测数值与对标结论，数值见《创新点指标盘点.md》、对标见《创新点对标分析.md》。

> 设计盘点：2026-11-22。本文只定义产品与技术方案，不代表新增功能已经实现。凡标为“现有”的指标，页面都必须从在线数据源读取，不得把本文件里的历史快照写死为当前值。

## 结论先行

建议建设一个**学生、教师共用的「创新全景」独立板块**，按角色返回不同数据范围，页面采用三屏纵向叙事：

1. **结果导向**：从“推荐了多少岗位”转向“学生是否获得真实面试机会”，同时明确当前系统尚未采集真实投递、面试邀约与录用事件。
2. **测—推—练—补**：把学业成绩、课程技能、可解释岗位推荐、模拟面试、课程补强串成可核验的证据链。
3. **可信数据与区域产业**：展示数据来源、原文链接、核实/采集时间，并以岗位供给与学生兴趣信号呈现区域产业分布。

**关键边界**：目前没有真实“有效面试机会数”、投递转化率、录用率或补强完成率的数据表；`面试会话`记录的是 AI 模拟练习，不是真实企业邀约。广西模式“成功率 +60%”在代码库中未找到可核验的来源、样本与分母，不能作为启航效果数据展示。MVP 不新增业务表，以现有 MySQL / DuckDB 数据和确定性引擎构建看板；真实就业结果 KPI 作为后续数据采集项目单独立项。

## 一、信息架构与挂载位置

### 挂载方案

新增共用视图 `web/src/views/InnovationHub.vue`，挂到学生与教师各自的登录后路由：

- 学生：`/student/innovation`
- 教师：`/teacher/innovation`
- 学生侧数据只读取 JWT 对应的本人；教师侧只显示租户内、任教范围内的聚合数据，不返回面试原文或跨班学生明细。
- 侧栏增加一项「创新全景」作为演示入口；不把现有页面改成暗色，也不把三屏做成三条新路由。桌面端用单页滚动叙事，移动端改为顺序单列。

板块的跨域属性（学业、岗位、面试、知识来源）不适合塞进单一“岗位列表”或“面试实验室”内部，因此采用独立入口；同时复用已有 `OpportunityHub`、`InterviewHub`、`CampusInsight` 的数据能力，不复制业务算法。

### 三屏叙事

| 屏 | 讲什么 | 主内容与交互 | 可用事实 | 空数据时 |
|---|---|---|---|---|
| 1. 从推荐到结果 | KPI 从推荐数量转向学生实际获得的机会 | 一句价值主张 + 3 张事实卡：已完成模拟面试场次、所选岗位就绪度、岗位库记录数；右侧单独显示“真实面试机会数：尚未采集”，链接到指标口径说明 | `面试会话` finished 数、`engine.readiness` 就绪度、`岗位`记录总数 | 显示“尚未采集/当前无记录”，不将缺失画成 0；真实机会 KPI 不用模拟场次代替 |
| 2. 测—推—练—补 | 学业如何成为岗位证据，差距如何回到下一步训练 | 4 步路径：测（成绩/测评）→ 推（匹配分与命中/缺口）→ 练（题库出题、追问、引擎评分）→ 补（技能/课程建议）；可展开一张“岗位技能—课程成绩—简历证据—面试漏项”的本人实例 | `engine.recommend`、`engine.readiness`、`engine.interview`、`engine.attribution`、课程技能图谱 | 缺课程映射时明确写“未找到课程映射”；建议动作只标“建议”，不得展示成已完成 |
| 3. 可信事实与区域产业 | 数字能回到出处；岗位供给和兴趣热度分开呈现 | 左：来源/发布日期/核实或最近采集时间卡；右：城市×行业岗位供给矩阵（数据足够才显示热力图）及独立的浏览/收藏兴趣排行；每张图可切到表格 | `招聘岗位`、`招考公告`、`考证目录`、`抓取运行日志`、`岗位浏览日志`、知识库引用 | 数据量不足时降级为排序条形图或空态；供给与兴趣是不同分母，禁止合并成“成功率” |

教师模式把第 2 屏中的个人证据链替换为班级聚合摘要（任教范围、租户过滤在数据层完成）；第 3 屏的学生兴趣只提供去标识化的班级汇总。未经隐私与样本量审查，不展示学生姓名、简历、原始回答或小样本可识别的分组。

## 二、创新点卡片与真实数据来源

### 可展示卡片

| 卡片 | 当前真实来源与口径 | 当前状态 | 展示与降级规则 |
|---|---|---|---|
| AI 工具链 / RAG 可追溯 | `db/rag_tables.sql` 的 `知识库文档`、`知识库分块`、`对话消息.工具`、`对话消息.引用`；引用可带文档、页码、块号；`agents/tools.py` 注册表与 `agents/graph.py` 分发是代码能力证据 | 能力与留痕结构已存在；没有统一的“回答准确率”实测指标 | 展示一个真实引用样例及其文档/页码/块号，或展示当前已有调用留痕；不得把“调用次数”说成准确率。没有引用时显示“本次无可回溯引用” |
| 可解释岗位推荐 | `engine/recommend.py::score_job()` 返回 `final_score`、`dims`、`hit_items`、`gap_items`、`action_items`；DuckDB `推荐日志`保存内容/协同/最终得分、命中项、缺口项、引擎版本和创建时间 | 真实打分与理由字段存在；推荐分是匹配度，不是面试/录用概率 | 选一条实际推荐展示“匹配分 + 命中证据 + 缺口 + 下一步”；无结果返回空列表并提示岗位池或画像条件不足，不由模型补岗位 |
| 学业—技能—岗位关联 | `engine/readiness.py::assess()`；MySQL `成绩`、`课程`、`简历`及经历/技能表、`岗位.技能标签`；课程技能映射走 `engine.kg.skills_for_course()` | 真实引擎结果含 readiness、proven/hidden/claimed/weak/gap 分类、课程/简历证据 | 分数只显示引擎返回值和版本；未修课、无分数、无岗位技能分别显示“缺数据/岗位未标注/未匹配”，不填 0、不做近似课程冒充 |
| 测评—推荐—模拟面试—补强闭环 | 测评：`engine/assessment.py` + `测评结果`；推荐：`engine/recommend.py`；练：`面试会话`、`面试问答` + `engine/interview.py`；补：`engine.attribution` / `engine.readiness` 的缺口与行动 | “测、推、练、给补强建议”已有底子；系统没有补强动作完成/课程选修后的闭环事件 | `面试总分`明确标“模拟面试引擎分”；显示补强建议，不显示“已补齐率”或“补课完成率”。空护照为 `sessions=0` / 空趋势，不伪造基线 |
| 能力成长 | `app/routers/interview_lab.py` 的 `/interview/lab/summary`、`/interview/lab/passport`；`engine/passport.py::build_passport()` 提供已完成场次、雷达、趋势、首末场差值与下一步动作 | 对同一学生已完成的模拟面试可确定性计算；无场次时趋势与成长差值为 `null` | 1 个数用统计卡；不足 4 个趋势点用统计卡/逐场列表；有足够点再画趋势线。差值必须标明比较的是首末模拟场，而非就业结果 |
| 失分回到课程 | `app/routers/interview_lab.py::attribution()`；`engine/attribution.py::attribute()`；MySQL `成绩`、`课程`，并取专业/年级同课成绩分布和 KG 课程技能映射 | 课程/成绩/图谱命中时可归因；缺映射会有 unmatched/unknown | 展示“命中哪题、漏了什么、对应哪门课/成绩”；无映射时标“暂无法归因”，不编课程名、不推断学生基础薄弱 |
| 官方事实核验 | `考证目录`有来源标题、来源链接、`核实日期`；`招考公告`有原文链接、发布日期、最近发现时间；`招聘岗位`有来源、投递链接、发布日期、最近发现时间；`知识库`引用有文档/页码/块号 | 官方考证目录具有明确核实日期；招聘/招考源记录的是抓取/最近发现时间，不等于人工核实日期；知识库文档创建时间也不等于事实核实时间 | 标签严格区分“核实于 YYYY-MM-DD”“发布于 YYYY-MM-DD”“最近抓取到 YYYY-MM-DD”。缺链接或日期保持缺失并提示，不补默认值 |
| 区域产业热力 | 岗位供给：`岗位`（城市/行业/发布时间/来源）与 `招聘岗位`（租户/城市/行业/状态/发布日期/最近发现时间）；兴趣：`岗位浏览日志`的岗位编号、动作、学期/创建时间，关联岗位维度 | 岗位供给和浏览/收藏兴趣的字段都存在；它们反映“供给/兴趣”，不代表就业结果 | 两类数据分图并标注口径和时间范围；招聘岗位在招数必须从 `招聘岗位.状态='open'` 过滤并带租户条件；静态 `岗位`只能标“岗位库记录”，不能标“当前在招” |
| 学生—教师协同 | `engine.teacher_career.build_class_career_report()` 输出班级人数、预警数/率、均分、意向分布、岗位匹配摘要；校园洞察有任教班级聚合 | 聚合引擎存在；学生端只能本人，教师端只能被授权任教范围 | 教师只看按租户/班级范围聚合的结果，不把学生端接口参数开放成任意 `student_id` 查询；小样本显示样本说明 |

### 不存在或不可作为当前 KPI 的数据

| 指标/说法 | 代码库核验结论 | 看板处理 / 可用的真实替代 |
|---|---|---|
| **有效面试机会数** | 未发现投递事件、企业面试邀约或面试结果表；`面试会话`是 AI 模拟练习 | KPI 卡标“尚未采集”，不显示 0。旁边可单独展示“已完成模拟面试场次”和岗位供给数，明确二者不是有效面试机会 |
| **广西模式成功率 +60%** | 仓库未找到对应原始报告、来源链接、样本、分母、时间范围或对照组 | 不进入页面，不写入示例数字。替代为本地真实“岗位供给城市/行业分布”“个人/班级岗位就绪度”，并标口径；若要引用外部案例，先补可公开核对的来源和统计定义 |
| 推荐投递率、面试邀约率、录用率 | 没有推荐→投递→邀约→录用的用户确认/核验事件链 | 不画漏斗、不推算转化率；如需后续 KPI，单独建设带授权与核验状态的求职进展数据 |
| 补强完成率 / 课程补齐率 | 目前只有引擎生成的建议，没有建议被接受、执行、完成的持久化事件 | 展示“建议补什么”和现有选课/成绩事实，不说“已完成”；未来要统计需接入真实选课/完成状态 |
| “岗位当前在招数”（复用 `/job/stats.open`） | `app/routers/job.py:182-218` 当前从 `岗位` 表用 `COUNT(*) AS open_n`，而 `岗位` 表结构没有状态列；该 `open` 不能证明在招 | **此字段是展示阻塞项**：修正聚合后才能展示；短期只用“岗位库记录数”，或从 `招聘岗位` 按真实 `状态='open'` 与租户筛选统计 |

### 历史数据快照的使用边界

`docs/data_usage_map.md:3` 标明其行数是 2026-11-16 的 MySQL `information_schema` 盘点快照。该文档记录当日 `岗位` 2,931 行、`招聘岗位` 219 行、`面试会话` 20 行、`面试问答` 107 行等。以上只可用于设计盘点/验收对照，**不得作为当前页面的静态 KPI**；上线页面须实时查询并显示 `as_of` 时间、样本范围和数据源。若查询失败，显示错误/重试，不保留成看似实时的旧值。

### 数据与 API 设计（MVP 不加新表）

- **表结构**：MVP 复用现有 MySQL/ DuckDB 表，不新建业务表；只新增看板读模型字段。每张卡返回 `available`、`value`、`unit`、`as_of`、`scope`、`source_table/source_fields`、`engine_version`、`note`。缺失值用 `null` + `available=false`，不可用 0 代替。
- **引擎**：新增纯函数 `engine/innovation.py::build_innovation_overview(inputs, role_scope)`，只聚合现有引擎结构化输出，不连数据库、不调用 LLM、不重新计算推荐分/面试分、不把预计值升级为确定事实。
- **路由**：新增 `app/routers/innovation.py` 的 `GET /innovation/overview`，从 JWT 取得角色/租户/身份。学生只取本人事实；教师仅走既有教师范围校验后聚合。同步在 `app/main.py` 注册路由。数据库查询使用参数化 SQL；来源卡按角色脱敏。
- **前端挂载**：新增 `web/src/views/InnovationHub.vue`；`web/src/router/index.js` 分别在 student/teacher 子路由下挂载同一组件；`web/src/layout/ShellLayout.vue` 增加“创新全景”入口。前端只渲染 API 数值与来源，不自己算分、人数、比例或趋势差值。

### 后续真实结果 KPI（非 MVP，先决条件未满足）

只有业务方确认采集授权、隐私/留存策略、核验职责和口径后，才新增 `求职进展`（名称可在评审时定）事件表。最低数据契约应覆盖：租户/学生、可关联的岗位编号或岗位名称快照、事件类型（申请/邀约/参加/录用/拒绝/撤回）、事件时间、来源、核验状态与核验时间、创建时间；不得存放不必要的邀约截图/身份证明原文。建议“有效面试机会”定义为**去重后的学生—岗位组合中，有学生确认且核验状态为 verified 的真实企业面试邀约**；模拟面试、仅投递、未核验邀约不计入。事件采集和口径通过评审前，页面只显示“尚未采集”。

## 三、科技感视觉规范边界

### 不能推翻的基线

沿用 `web/src/styles.css` 的浅色画布、近黑正文、单一靛蓝主色、12px 卡片圆角与可见焦点态；主按钮固定 `#1951c3`。科技感只用于局部数据视图和一块深色展示区，不能把整页改成暗色、不能铺满霓虹渐变、不能让装饰盖过来源与数值。

### 图表与微动效清单

- **图表选型**：单值用统计卡；面试场次趋势有足够数据点时用单系列折线；少于 4 个点用统计卡/逐场列表；岗位城市/行业比较用同色水平条形图；仅在至少 20 个有效城市×行业单元时显示单色阶热力矩阵，否则回退排序条形图。热力图必须同时提供可排序表格、键盘焦点读数、数值图例和数据时间范围。
- **配色**：数值大小用同一靛蓝色阶，不用彩虹；极性/风险只用既有语义色。区域、岗位类别是名义类别，不按数值/排名换色；数据不足或颜色无法区分时用文字、标签或表格补充。禁止双 Y 轴和“颜色越红成功率越高”这类未定义语义。
- **图表细节**：网格线 1px 浅灰；柱体不超过 24px 厚、末端 4px 圆角、柱间留 2px 背景缝；折线 2px；数值/分类文本不能只在 tooltip 中出现。每图有可访问名称、精确数值表格与加载/空态/错误重试态。
- **局部光效**：仅第 1 屏 Hero 或第 3 屏的数据展示块采用 `--qh-innovation-display-bg`；背景只加一到两团低透明靛蓝/青色 radial-gradient，不做全屏粒子/持续扫描线，不降低文字对比度。
- **进入与状态动效**：卡片内容用 opacity + `translateY(4px)`、180–240ms；条形仅用 `transform: scaleX()` 展示数值到达；按钮 hover 只改变边框/浅色/阴影，不让布局跳动；来源链接 hover 只强调下划线/图标。不做大数字假滚动、自动播放轮播或长距离视差。
- **可访问性**：`prefers-reduced-motion: reduce` 时关闭进入/脉冲/渐变动画；键盘焦点沿用 2px 可见焦点环；普通文本对比度至少 4.5:1；状态不可只用颜色；375px 手机不横向溢出，图表下方始终可查看表格/数据摘要。

## 验收红线

1. 每个展示数字都能指回 MySQL/DuckDB 字段或确定性引擎版本，并显示口径/时间范围。
2. “模拟面试分”不写成企业面试表现；“岗位匹配分”不写成录用概率；“建议动作”不写成已完成。
3. 数据查不到时显示空态与原因；禁止模型记忆、示例值或历史快照补数。
4. 学生本人数据只归本人；教师侧遵守租户与任教范围隔离；不展示原始隐私材料。
5. 新功能测试覆盖数据来源、确定性聚合、空值、权限、桌面/移动与可访问性；通过评审后再安排部署。

## 创新全景页视觉规范（2026-11-24）

### 1. 布局
- KPI 事实卡为三列网格（`repeat(3, minmax(0, 1fr))`）；≤1180px 降为两列，≤700px 降为单列。
- 屏 3 用 `grid-template-areas` 分区：`'supply supply'` / `'sources interest'`；供给热力矩阵占满首行，来源卡与兴趣排行并列第二行。≤1180px 改为 `'supply'` / `'sources'` / `'interest'` 单列顺序。

### 2. 模数
- 卡片圆角：`var(--bento-radius, 16px)`。
- 卡片内距 20px，页面内距 24px（沿用 `.bento-page`）；步骤卡内距 18px。
- 屏间距 32px，网格 gap 20px。
- 断点：1180px、700px。

### 3. 字号层级
- 页 h1：`clamp(19px, 1.8vw, 22px)`。
- 屏 h2：`clamp(17px, 1.6vw, 21px)`。
- 卡片标题 14–15px（来源/图表标题 14px，步骤标题 15px）。
- KPI 数值 34px / 700 / `font-variant-numeric: tabular-nums`。

### 4. 色板
- 单一靛蓝主色阶：`#123a8f` / `#1951c3` / `#3f70d4` / `#6c92e9`（步骤四段取值）；供给热力矩阵同一色系 ramp 为 `#cddaff` / `#9db8f5` / `#6c92e9` / `#3f70d4` / `#1951c3`。
- 状态语义色：teal `#0f9d8a` 表示已核实，amber `#c98900` 表示未采集；状态同时带文字标签，不只靠颜色。
- 深色 Hero 块 `#0b1220`，仅用于第 1 屏 Hero。

### 5. 动效
- CSS 过渡统一 260ms（`--qh-innovation-ease`）；ECharts series 动画为 220ms。
- reveal 使用 IntersectionObserver 逐项触发（threshold 0.12），3 秒后兜底全部显示；`prefers-reduced-motion: reduce` 时关闭。

## 全国岗位供给地图：数据来源与合规说明（2026-11-24）

### 1. 边界数据来源
- 省级边界取自阿里云 DataV.GeoAtlas 省级边界（`areas_v3` 的 `100000_full`），落地为项目静态文件 `web/public/geo/china.json`。
- 文件共 34 个省级行政区 feature（含台湾省、香港特别行政区、澳门特别行政区）和 1 条九段线要素（adcode `100000_JD`）。
- 运行期通过 `fetch` 读取本地文件并调用 `echarts.registerMap`，不依赖任何外网地址。

### 2. 合规边界
- 不使用 Google Maps、Apple Maps、Bing 海外版、OpenStreetMap 直连瓦片、Mapbox、Leaflet+OSM 等未取得资质的境外来源。
- 本图不接第三方瓦片底图、不做定位与路线服务，仅作行政区划矢量统计图。
- 若后续需要交互底图、POI 检索或路径规划，改用腾讯地图、高德、百度或天地图，由使用方自行申请 key；前端代码只保留占位符，禁止内置可用 key。

### 3. 口径
- 省级数值由「岗位」表按城市在库岗位条数（快照）经城市到省映射求和得到。
- 未映射城市不计入聚合并如实显示个数。
- 该数值不表述为招聘需求、就业率或转化率，也不与浏览收藏行为相除。

### 4. 技术约束
- 关闭 geo roam，防止演示误操作。
- 不引入瓦片。
- 地图仅在第三屏作为宏观分布视图，城市×行业明细仍以热力矩阵呈现。
