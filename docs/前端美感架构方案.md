# 启航前端美感与架构提升方案

> 审视日期：2026-11-22。本文是设计与迁移方案，不代表所有改造已经实现。基线以 `web/src` 当前代码和真实浏览器截图为准。

## 1. 结论先行

启航前端已经有清晰的浅色工作台骨架：Vue 3 单文件组件、按路由懒加载、Element Plus 按需引入、Bento 4 列布局、局部深色数据展示层。当前最影响观感的不是“缺少特效”，而是**同一视觉概念存在多套值与多套交互规则**：`styles.css`、`styles/bento.css`、`styles/readability.css`、`styles/motion.css`、`styles/tech.css` 以及页面 scoped 样式分别定义卡片圆角、阴影、字阶、hover 和渐变；后加载的 `tech.css` 用 `!important` 覆盖前层，导致不同页面看起来像不同产品。

建议目标不是推翻浅色体系，而是建立一个「单一底、单一卡、单一主按钮、单一动效节奏」的系统：背景退后，卡片边界稳定，数值与事实前进，装饰只用于局部数据可视化。所有数值来源、身份注入、引擎口径与路由结构保持不变。

## 2. 现状问题清单

| 层面 | 当前事实 | 问题 | 建议 |
|---|---|---|---|
| Token | `styles.css` 有 `--cf-* / --qh-* / --el-*`，`bento.css` 有 `--bento-*`，`tech.css` 有 `--tech-*`，`readability.css` 再覆盖字号 | 同一语义多层命名，页面可用任意一组，迁移时无法判断真相源 | 以 `--qh-*` 为唯一设计 token；其它变量作为兼容别名，分阶段替换 |
| 卡片 | 全局 `el-card` 12px 圆角，`bento.css` 20px，`StudentHome` 等页面还有 16/18px | 相邻卡片边界不对齐，阴影深浅不一致 | 一套 `.qh-surface` 规范：12px 主卡、16px 局部展示卡；禁止第三种卡片圆角 |
| 阴影 | `styles.css`、`bento.css`、`readability.css`、`motion.css`、`tech.css` 各自定义不同阴影与 hover 抬升（-2/-3/-4px） | hover 像随机跳动，白卡周围出现蓝雾 | 静态单层阴影 + hover 仅边框/背景变化；浮起最多 2px 且仅链接型卡片 |
| 顶栏 | `ShellLayout` 白底 scoped 样式，`tech.css` 毛玻璃渐变再用 `!important` 覆盖 | 后加载文件覆盖组件本身，调试成本高，滚动时发丝线颜色变化 | 顶栏状态写回 `ShellLayout` 的 scoped 样式，`tech.css` 只保留局部可视化工具类 |
| 字号 | `styles.css` 15px、`readability.css` 16px、Element Plus 变量被重复覆盖，页面私有 12.5/13.5/14px 密集 | 不同页文字密度差异大；窄屏与投影可读性不稳定 | 正文 16px/1.65，辅助 14px/1.5，标题 20/24/30 三档；小于 13px 仅用于图表轴标签 |
| 色彩 | 主色 `#1951c3`，但 `tech.css` 有蓝→青渐变、发光、深色面板；Bento 旧注释仍有紫蓝 | 装饰色占比过高，语义色与强调色容易混用 | 主色只用于主按钮/链接/焦点/选中；红橙绿只表达预警状态；深色仅局部数据可视化 |
| 动效 | `.qh-reveal` 对大批量卡片依次入场，`motion.css` 与 `tech.css` 双重路由淡入、扫光、浮动、hover 边光 | 多个动画竞争注意力，业务数据页面像落地页 | 动效只表达状态变化：hover/press/focus/展开/路由；删除无限扫光、滚动渐变、全卡发光 |
| 信息密度 | StudentHome 曾有跨两行卡与第二行空区；教师页/hero/筛选/表格行距各异 | 空白位置由 CSS 跨行规则而非内容决定 | 用等高双栏或明确「结论 → 明细 → 行动」分组；空区只由真实数据模块填充 |
| 响应式 | Bento 在 1180px 降到 2 列、700px 降到 1 列，页面另有 900/560/760 等断点 | 断点不一致，局部规则互相覆盖 | 统一断点 1440/1024/768/390（实现值 1180/700 兼容现有栅格），页面私有断点只许收窄内容，不得改栅格列数 |

## 3. 页面层次与留白节奏

### 3.1 三层结构

1. **全局壳层**：`ShellLayout.vue` 负责品牌、身份、状态、主导航、通知入口、移动端抽屉和路由焦点；整站位置固定，不随页面换肤。
2. **页面结论层**：一个 `RouteHero` 或等价页头，只回答「本页结论是什么、这组数据来自哪个引擎/时间范围、当前主操作是什么」。每页最多一个填充式主按钮。
3. **工作区层**：Bento 栅格负责主体内容。第一屏显示与当前任务最直接的数据/图表/列表；次要证据、原文链接、流程记录放后半屏。筛选器、指标卡、详情卡使用同一套卡片与间距。

### 3.2 垂直节奏

- 页面边距：手机 16px，桌面 24px；大屏不超过 32px。
- 模块之间：16px（组件内）、20px（卡片间距）、24px（分组间距）；禁止 18/22/26/30px 这类随意值。
- 卡内：标题 → 8px → 辅助说明 → 16px → 内容；内容区底部 16px；footer 用 1px 分隔线且不再嵌套卡片。
- 表格/列表：行高 48px（密集数据 44px），组标题与首行之间 12px；长文本优先换行，只有 ID/链接等可中断串允许省略号并配 `title`。
- 页面标题只在顶栏出现一次，卡片标题使用 16–18px，不重复页面级标题。

### 3.3 双栏对齐原则

`StudentHome` 的修复即为规则样例：左侧长内容占两行时，右侧必须用真实数据模块补齐同样高度，不能只放一张短卡后留空；摘要卡优先复用现有接口返回值（岗位标题、公司、城市、匹配分、缺口），不生成完成率、雷达分或倒计时。2 列栅格下长卡只占 1 列并跨 2 行，右侧两张卡各 1 列 1 行；单列栅格恢复自然顺序。

> 注：上表用于说明别名方向。正式改造时，先定义不重名的新 token（例如 `--qh-bg-color` / `--qh-surface-color`），再让旧变量指向新值；现有 Vue 页面中的 `--qh-surface / --qh-text / --qh-primary` 需先完成命名迁移，避免自引用。

颜色使用红线：

- 普通文本对白底至少 4.5:1；辅助文字不用低于 `#6b7280`。
- 主色占单屏面积不超过约 3%，只用于主按钮、链接、焦点环、当前态和关键数据线。
- 红/橙/黄/青绿只表达预警语义，不用于装饰；状态必须同时有文字或图标。
- `--tech-dark` 仅用于数字孪生核心、图表展示区等局部可视化，禁止套到页面根容器或顶栏。
- 不引入紫/薰衣草色；已有旧注释中的紫蓝渐变视为历史债务，后续由主色实底替换。

## 5. 组件一致性清单

| 组件/模块 | 当前基线 | 统一职责 | 视觉契约 |
|---|---|---|---|
| `AppShell` | `web/src/layout/ShellLayout.vue` | 导航、身份、状态、通知入口、移动端菜单、焦点返回 | 侧栏 236px、顶栏 64px；标题、身份、状态同一行；移动端导航为全屏抽屉 |
| `RouteHero` | `web/src/components/brand/RouteHero.vue` | 每页一条结论 + 2–3 个引擎指标 + 最多 2 个动作 | 白面、12px 圆角、1px 边；指标数值等宽；语义色只染数值 |
| `SurfaceCard` / `.qh-surface` | `bento-card` 与 `el-card` 混用 | 卡片、筛选区、列表、详情的统一容器 | 12px 圆角、`--qh-shadow-card`、20px 内边距；卡内最多再嵌一层浅面 |
| `MetricTile` | 多页私有 `.stat-card / .kpi / .route-stat` | 标签、数值、单位、口径/来源、缺失状态 | 数字 20–24px、tabular-nums；缺失写「— / 暂不可用」，不写 0 |
| `FilterBar` | `.filter-bar`、`HubBar.vue`、各页 `el-form inline` | 条件、结果数、重置、查询、窄屏折叠 | 同一行控件 40–44px 高；移动端换行而非压缩文字；查询按钮每区一个 |
| `DataList` / `StatusTag` | `notice-item`、`rec-cell`、`comp-cell`、`el-table` | 数据行、状态、来源、动作、空态 | 行高 44–48px；标签统一 pill；状态文字 + 色点；链接末端箭头一致 |
| `NoticeCenter` | `StudentHome.vue` 的竞赛通知抽屉 | 通知分类、未读、来源、推送授权、标记已读 | 列表按日期倒序；未读作单点/文字，不闪烁；授权状态可见、可撤销 |
| `EmptyState` / `ErrorState` | `el-empty`、各页 `v-if` 文案 | 空数据、加载失败、重试 | 明确原因 + 下一步；禁止用示例数据、历史快照或 0 冒充 |
| `AppDrawer` / `AppDialog` | `el-drawer`、`el-dialog`、`.drawer-panel` | 详情、表单、确认 | 关闭按钮、Escape、焦点回到触发元素；标题与正文间距 16px |
| `MotionTokens` | `styles/motion.css`、`styles/tech.css`、`useReveal.js` | 受控状态动效 | 只用 `transform/opacity`；统一时长；`prefers-reduced-motion` 全部静止 |

### 组件改造优先级

1. **先收口全局 CSS**：建立 token → 删除 `tech.css` 中对全局 `el-card`、顶栏、路由过渡的 `!important` 覆盖 → `motion.css` 只保留状态动效。
2. **再做共享组件**：`RouteHero`、`SurfaceCard`、`MetricTile`、`FilterBar`、`EmptyState` 以现有结构为基础做样式类，不改 props 与数据流。
3. **后做页面迁移**：StudentHome / TeacherDashboard / CampusInsight / OpportunityHub / PlanHub 逐页替换私有字号、圆角、阴影；每页 build + 桌面/手机截图验收。
4. **不一次性重写**：不引入 UI 框架替换 Element Plus，不改路由懒加载，不把所有页面改成同一个营销页。

## 6. 动效克制原则

| 场景 | 允许 | 禁止 |
|---|---|---|
| Hover | 链接型卡片上移 2px、边框加深；按钮背景/边框渐变 180ms；链接下划线绘制 | 整页所有卡片一起浮起、发光扫边、彩色光晕 |
| Press / active | `scale(.98)` 120ms 或仅背景变深，不改变布局 | 位移动画、嵌套缩放、动画结束才提交状态 |
| Focus | 2px `--qh-focus` outline + 2px offset，立即出现 | 去掉 outline、只用淡到看不见的 box-shadow |
| 路由切换 | 0.18s 出场 + 0.24s 入场，仅 opacity + `translateY(8px)` | blur、scale、双文件重复覆盖、长距离位移 |
| 数据加载 | 骨架屏或局部 loading，内容区保留原尺寸 | 整页淡出、数字假滚动、闪烁占位 |
| 首次入场 | 每页最多 hero 一次，240ms；列表不做逐项交错 | 每张卡片都 `.qh-reveal`、滚动触发全页渐显 |
| 装饰动画 | 仅数字孪生等局部可视化允许低幅循环，且尊重系统设置 | 常驻漂浮、呼吸、扫光、无限粒子堆叠 |
| 减少动态效果 | `prefers-reduced-motion: reduce` 下所有 transform/animation 停止，内容直接可见 | 只降低速度或保留无限循环 |

动效仅表达因果关系：指针悬停、按下、聚焦、展开、页面切换。数值变化不靠动画暗示增长，通知未读不靠闪烁催促。

## 7. 信息密度优化规则

- 首屏默认展示：一句结论、关键指标、主要工作区入口；不把多个并列主按钮、状态说明、来源注释同时塞入首屏。
- 指标卡只展示确定性引擎返回值，保留单位、引擎版本与时间范围；`null` 显示「暂不可用」，禁止前端计算百分比/完成率。
- 表格与图表二选一：趋势用折线，分类比较用水平条，精确值同时提供表格或悬浮读数；颜色不能单独表达含义。
- 长说明折叠为「原文/口径」展开，不在页面铺满；详情页用正文段落，不用连续卡中卡。
- 任何空区先判断是否是栅格跨行造成；若是，用有真实数据的等宽模块补齐，或取消跨行，不用装饰图填空。
- 390px 手机：所有卡片单列，按钮 44px 以上，表格内部横向滚动但页面不横向滚动；长中文不强行一行省略。

## 8. 通知中心增强与 Web Push 的界面约束

- 通知中心沿用浅色卡片，不新增深色全屏层；分类为「竞赛通知 / 考证节点 / 招考机会」，类别由真实 `source/kind` 字段决定。
- 未读是状态点 + 文字，角标用 `role="status" aria-atomic="true"` 播报完整语义，例如「3 条未读通知」，不播报裸数字。
- Web Push 授权卡是显式状态机：`未配置 / 浏览器不支持 / 待授权 / 已开启 / 已拒绝 / 已关闭`。只在用户主动点击时请求权限；拒绝后不反复弹窗。
- 关闭推送同时调用退订接口并清除当前设备状态；失败保留旧状态并给出重试，不静默假装关闭。
- 点击系统通知只聚焦已有页面或打开本人通知中心，不把外链 URL 直接注入 Service Worker；数据只来自服务端已核验通知。
- 站内「全部已读」继续复用现有水位接口，不在新组件里另造已读状态或修改通知生成规则。

每轮验收：

1. `npm run build` 通过，`git diff --check` 无错误。
2. Playwright 真实浏览器截图 + 控制台错误为 0；允许只读 fixture，不使用模型记忆或静态快照冒充实时数据。
3. `prefers-reduced-motion: reduce` 下动画停止且内容可见。
4. 键盘 Tab 顺序与视觉顺序一致，焦点不被顶栏/抽屉遮挡。
5. 截图按 1440 / 1024 / 768 / 390 四档留档，记录版本与时间。

## 10. 不扩大的边界

- 不改预警、推荐、规划、考证、通知水位的引擎计算与业务规则。
- 不改 JWT 身份注入和租户隔离；新增通知订阅只从当前学生 JWT 取身份。
- 不引入新 UI 框架、不重写路由结构、不把浅色工作台改成深色落地页。
- 不把部署产物、其他协作者文件或自动构建生成的 `dist` 当作设计系统源文件。
- 全站迁移按独立小步提交；每次只提交本轮明确修改的文件，提交信息使用 `[阿衡]` 前缀，push 前先同步 rebase。
