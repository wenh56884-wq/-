### 1.1 对标要点归纳

- **商业平台（1–3）**：创新集中在「结果型指标、AI 助手/多智能体、交付时效」，本质是**流量与匹配效率**的竞争；量化口径多为**企业宣传口径**，普遍缺官方可核对的统计出处。
- **国家平台（4）**：强在**全国覆盖 + 就业态势感知（管理侧驾驶舱）**，是政务级基础设施，但面向个体学生的过程性诊断不是其重心。
- **高校平台（5–7）**：强在**场景贴合**——情绪陪伴（浙大）、测推练补闭环（哈工大）、四层架构闭环（广西）；但多为**单点能力或校方宣传口径**，量化成效（如 +60%）缺官方核实。

## 2. 启航系统现有创新点逐条对照

> 启航侧每条给出**代码/契约实证**，再对照上表说明「对齐谁 / 差异在哪」。五点口径与主控大创叙事一致。

### 2.1 AI 助手工具链

- **实证**：`agents/tools.py` 工具注册表（`TEACHER_TOOLS` / `STUDENT_TOOLS`，教师 14 / 学生 16，覆盖预警、成绩、学业预测、报考分析、岗位、图谱、招考、面试、题库、规划、竞赛、考证等全板块）；`agents/graph.py::_dispatch` 分发；`agents/auto_plan.py` 自主规划；`agents/brain.py` 多跳「规划→调工具→观察→反思→汇总」。三处注册同步由 `tests/test_agent_entry.py` 守卫（AGENTS.md §3）。
- **对标**：对齐 **#2 智联多智能体、#1 BOSS直闪闪、#4 智慧小业** 的「AI 助手」形态。
- **差异**：启航不是单点聊天助手，而是**覆盖学业+就业全板块的统一对话入口**，且叠加三重治理——身份只从 JWT 注入（铁律 2）、数据层租户隔离（铁律 3）、Critic 数值回查（铁律 1）。商业助手拿不到高校过程性数据，也做不到这种确定性治理。

### 2.2 全链路可解释推荐打分

- **实证**：`engine/recommend.py` 规则打分 + 三段式理由 + 协同过滤（hybrid-v1）；`engine/readiness.py` 岗位就绪度按**证据等级**（proven 有成绩单背书 / hidden 被埋没的资产 / claimed 只有自述 / weak 学过没学牢 / gap 空白）；`engine/attribution.py` 失分溯源到具体课程与分位；`engine/peer.py` 同辈分位基准。
- **对标**：对齐 **#7 广西「智能匹配」、#1 BOSS「达成」、#3 猎聘匹配** 的「匹配/推荐」能力。
- **差异**：商业平台的匹配度**只能读简历自述**；启航能交叉「课程成绩 × 岗位技能标签 × 课程-技能图谱 × 简历原文」四张表，回答「我学过也考得不错，为什么简历看起来什么都不会」，并把每个分数**回溯到证据**（哪门课、多少分、专业什么位次）。这是「可解释 + 证据链」，不是黑盒匹配分。

### 2.3 数据带依据链接 + 核实日期

- **实证**：考证中心契约 §27——`考证目录` 每条含**依据公告链接 + 核实日期**，「只放能核对的官方信息；官方未公布的标『预计』并写明推算依据，缺失不冒充」；招考公告 / 国考职位走官方源同步（`app/guokao_sync.py`、`etl/exam_positions.py`）。**本对标文档本身即遵循同一口径**。
- **对标**：对照 **#1–#7 全部**——头部平台量化口径多为企业/校方宣传，普遍**不附可核对的官方出处与核实日期**。
- **差异**：这是启航的「**数据诚信**」创新——每条外部事实附官方依据链接 + 核实日期，官方未公布即标「预计」，可溯源、可审计。对标平台的「65%」「5 秒千份」「+60%」恰恰是这一治理口径要约束的对象。

### 2.4 学生 / 教师 / AI 助手三端闭环

- **实证**：学生端、教师端、AI 助手端（统一对话入口 `Assistant.vue`）；闭环核心是工作流审批「**学生发起 → 教师裁决 → 学生回看**」（契约 §22，`app/workflow_approval.py`，`/workflow/approvals/pending`、`/workflow/my-runs`）；副作用操作**只挂起不执行**，教师通过才跑，且以**提交者身份**取数；多租户隔离保证教师只看任教班级。
- **对标**：对齐 **#6 哈工大「测推练补」闭环、#7 广西「实战反馈」闭环、#4 24365 态势感知（管理侧）**。
- **差异**：启航闭环**跨「学生—教师—助手」三端**，且教师裁决是**人工审批治理**（不是纯自动执行），商业平台根本没有「教师」这一角色。高校独有的「师生协同 + 任教范围隔离」是商业与纯学生端产品无法复制的。
- **口径说明**：「三端」= **学生端 / 教师端 / AI 助手端**（主控大创叙事口径）；闭环实证即工作流审批「学生发起→教师裁决→学生回看」。

### 2.5 五智能体协作

- **实证**：`agents/career/nodes.py` 明确为「职业规划模块的 **5 个 Agent 节点**（画像解析 / 规则匹配 / 周监控 / 通知过滤 / 陪伴对话）」，README 目录结构亦标注「career 5 节点」；由 LangGraph 编排，`engine/career_rules.py` 确定性判定，`agents/critic.py` 数值回查、超限降级模板。
- **对标**：对齐 **#2 智联「多智能体」**。
- **差异**：启航五节点**各司其职**（解析/匹配/监控/通知/陪伴），且「**引擎定数、模型说话**」——凡算与判全由确定性引擎完成，模型只组织语言，Critic 防幻觉、可降级。这是**可治理的多智能体**，而非黑盒多智能体。
- **口径说明**：「五智能体」= **career 模块五节点**（画像解析/规则匹配/周监控/通知过滤/陪伴对话），**不是** Orca 研发智能体（后者为 4 个：Claude/Qwen/CodeBuddy/主控）。研发期另采用多智能体协同开发（文件主权、契约先行、主控统一合并，见 `docs/Orca-多智能体编排操作手册.md`），属工程方法，不计入「五智能体」口径。

## 4. 差异化定位与结论

1. **商业平台（BOSS/智联/猎聘）**：强在流量、匹配效率、交付时效，但**拿不到高校过程性数据**（成绩、考勤、校园行为），无法做「证据链可解释」，量化口径也多为宣传口径。
2. **国家平台（24365）**：强在全国覆盖与就业态势感知（管理侧），个体学生的过程性诊断与师生协同不是其重心。
3. **高校平台（浙大/哈工大/广西）**：强在场景贴合（情绪陪伴、测推练补、四层闭环），但多为单点能力或校方宣传口径，缺「数据可溯源 + 数值确定性治理」。
4. **启航的独占位置**：**高校全域数据（MySQL 54 张表，2026-11-24 information_schema 实查；另 DuckDB 3 张）× 确定性引擎 × 可解释证据链 × 依据可溯源 × 师生三端闭环 × 可治理多智能体**。这正符合面试实验室契约 v2 的创新判断标准——「**市面上没有同类 + 只有高校场景成立 + 必须吃到启航独有数据**」。
5. **一句话定位**：头部平台比的是「匹配得多快、送达得多快」，启航比的是「**每个结论有没有证据、每个数字能不能回溯、每条数据有没有官方出处**」——这是高校场景独有、且商业平台结构性做不到的可信智能。
